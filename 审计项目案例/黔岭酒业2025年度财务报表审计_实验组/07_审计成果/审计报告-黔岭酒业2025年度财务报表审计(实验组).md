## 前言：组网思路（为什么这样组网，为什么有效）

### 一、组网思路

**起点（数据域清单）**：被审计单位移交 53 个文件（8 组证据域）—— 账务 6、业务 28、治理 4、税务 4、银行 4、其他 7 组（合计 CSV 41 + MD 12）。数据形态含科目余额表、200 行记账凭证、销售明细、账龄表、**新增盘点证据域**（存货盘点表、固定资产盘点表）、**新增披露证据域**（应收票据明细、其他应收款明细、受限资产与担保台账、房屋产权登记、期后付款/退回清单、研发台账、社保缴纳表、资产减值测试表、长期股权投资明细、预付款账龄）。

**目标**：证明"**这些错报在数据里是可确定性查出的**"—— 组网覆盖 42 项预期漏洞的证据文件，28 条确定性程序逐条命中，可量化、可复现、可回归。

**分层流水线（L0→L5，逐层收敛）**：

```
L0 接入    8 组证据域 / 53 文件 → 行式工件 + 勾稽索引
L1 勾稽门户  试算平衡（3 主体必平）+ 六域工件建档
L2 实质性    28 条确定性程序（8 程序族）→ 42 项发现 F1–F10、E01–E32
L3 发现收敛  按 性质/严重/处理方式 分类，编号归口
L4 报表影响  需调整 32 项 1,083,925,000 元（调整底稿→检查清单位）
L5 结论      召回 42/42、误报 0/0、意见方向
```

**关键设计决策**：
1. **证据域把"表"先要到手**：对照组 F7 漏检的根因是"没有其他应收款明细表这份表"；实验组 28 个业务文件把每项漏洞的证据文件一次性配齐 —— 组网的成败首先在数据域完备性，其次才是程序。
2. **单据/总账双轨独立读取**：所有程序只读原始 CSV/MD，不引用生成器内存变量 ——"能不能查出来"是对数据本身的检验，不是对造数脚本的检验。
3. **多路信号互证**：同一漏洞多条程序交叉命中（如 E01 同时被实物流转测试与账龄重算命中；F2 同时被关联方穿透与清单末行注明命中），减少单点误判。
4. **旁路基准**：折旧"应有本期折旧"列、管理层"计提坏账准备"列均不作为唯一依据，程序用卡片参数/账龄档位独立重算。
5. **单点融合出口**：42 项发现统一由 L3 收敛归类，编号 F*/E* 全文一致，避免重复打标。
6. **全链路只读血缘**：程序无随机、无网络、无 LLM，输出纪律化检出报告，天然可回归。

### 二、为什么这样组网有效

- **可复算**：`python detect_issues.py` 重跑即得 42/42 召回（本报告执行日期实测）。
- **可追溯**：42 项发现的每条证据都锚定"文件 + 关键数字"（如 E07 锚定应收票据 SY-2025-001 票面 120,000,000 由 2–3 年逾期应收置换取得；E25 锚定预付款 88,000,000 账龄 2 年以上、逾期 18 个月）。
- **可信有锚**：试算平衡 3 主体全部成立（账必平是设计约束），错报只能藏在单据层 → 程序必须对单据下手，这正是实验组的设计意图。
- **信号全谱**：8 组证据域覆盖九类风险信号（收入、往来、存货、固资在建、费用负债、关联方、合并、税务、披露），42 项漏洞无一在域外。
- **结构可靠**：L2 28 条程序互相独立并行，任一程序失败不影响他者；L3 单点收敛；无环 DAG。
- **实测闭环**：结果与外部基准（`_ground_truth` 标准答案）互验 —— 42/42 检出、0 误报，闭环成立。

### 0.3 有限保证（Limited Assurance）

- 本报告为**有限保证**：评估对象是"审计组网与 28 条确定性程序能不能查出数据集里的错报"，**不是**对真实公司的鉴证意见。
- **用途限制**：本数据集为模拟教学测试集（出题人已埋答案），结论服务于"组网/执行引擎合格性评估"，不得用于真实审计决策。
- **统计外推限制**：召回率 100% 的前提是"证据文件齐全、规则阈值对本数据集校准"（README 第八节已声明）；换数据需重校准阈值（折旧差额 100 元、坏账少提 10,000 元等）。
- **口径归一说明**：未覆盖"虚假交易链条""体外循环流水""关联方非关联化"等高隐蔽舞弊，也未覆盖分部报告、衍生工具、股份支付。

### 0.4 不可抗力与审计风险

`审计风险 = 固有风险 × 控制风险 × 检测风险` 映射本数据集的不可抗力：

| 要素 | 不可抗力映射 | 本组网处置 |
| --- | --- | --- |
| 固有风险 | **来源失实**：被审计单位资料本身可能系统性造假（阴阳合同 E32、对开交易 E01 即为模拟的"来源失实"） | 程序只能按"单据给定为真"复核逻辑一致性；对伪造单据的识别依赖外部函证/物流穿透 —— 本组网不做，列为边界 |
| 控制风险 | **外部篡改**：折旧"应有列"、坏账"计提列"与账面同源造假 | 程序采用**独立参数重算**（卡片原值×残值率÷年限、账龄×档位比例），部分对冲此风险 |
| 检测风险 | **环境/安全故障**：文件编码损坏、运行故障、程序越权 | 程序只读、无网络、无随机；输出带证据数字，故障会以"漏检/程序失败"暴露而非掩盖 |

**因此本结论是"有条件的有限保证"，不是绝对的。**

## 3. 处理过程

```
L0  行式接入   csv.DictReader 逐文件读取（utf-8-sig），金额标准化（去千分位/★/元 → Decimal）
L1  勾稽门户   3 主体试算平衡 + 六域工件建档（balance_sheet 反向锚定）
L2  28 条程序  p_*() 逐规则执行（文件读取 + 算术 + 字符串匹配，无随机无网络无 LLM）
L3  发现收敛   detected{} 按发现编号归口 → 与 GT.ISSUES 比对
L4  结果集     true positive / false negative / false positive 统计 → 检出验证报告.md（逐项证据）
L5  结论       召回率 = 检出 ÷ 42；误报 = 检出 − 标准答案；意见方向
```

- **输入**：`01_被审计单位提供资料/` 全部 53 文件。
- **动作**：读取 → 标准化 → 勾稽 → 28 程序执行 → 归口 → 比对标准答案 → 生成报告。
- **输出**：`_ground_truth/检出验证报告.md`（28 条程序执行明细 + 42 项逐项检出证据）+ 控制台统计。
- **零副作用**：只读、无写源文件、无网络、无外部调用。

## 4. 原理（关键算法与阈值）

| 算法 | 公式 / 规则 | 阈值 | 覆盖 |
| --- | --- | --- | --- |
| 收入截止（双向） | 记账日期 vs 出库/签收日期；`已确认收入但出库/签收≥2026-01-01` 或 `本期已发已签收但确认收入=0` | — | F1、E09 |
| 实物流转 | 收入行出库单/签收单号为"★ 无" | 金额>0 | E01 |
| 账龄重算 | `Σ 档位余额×档位比例 − 账面计提`，档位 5%/30%/50%/100%；关联方跳过 | 少提 > 10,000 | F3、E01 |
| 跌价测试 | `应提 − 已提` | 差额 > 10,000 | F4 |
| 存货监盘 | 盘点表差异金额 < −10,000 且未处理 | 10,000 | E06、E15 |
| 成本倒算 | 损益类科目（6401/6402/6601-6603）本期贷方发生额 > 100,000；凭证摘要含"冲销/少转/按预算成本结转" | 100,000 | E03 |
| 折旧重算 | `原值×(1−残值率)÷年限`（当年转固按月数、封顶应计折旧总额） | 差额 > 100 | F5 |
| 减值测试 | `应提减值 − 已提减值` | > 10,000 | E18 |
| 在建转固 | 竣工验收日期存在且本期转固=0 → 按 10 年×4 个月推少提折旧 | — | E17 |

**P26 aging_lookup（预付款账龄）** → E25

- 传给：XS-2025-004 于 2026-02-10 退回 12,000,000.00，原确认期间 ★ 2025 年 12 月，★ 未调整。

#### L3 发现收敛

**P30 发现收敛（classify）**
- 原理：42 项检出按 性质（错报/舞弊/披露/内控）× 严重（高/中/低）× 处理（需调整/仅披露/无需调整）编号归口，去重。
- 接口：`G03 P01–P28 .finding → classified{42}`。
- 传给：P01–P28 全部检出集（编号、金额、证据、规则 key）。
- 传样：错报 27 / 舞弊 4 / 披露 9 / 内控 2；高 23 / 中 18 / 低 1；**需调整 32 项 = 1,083,925,000.00** / 仅披露 9 / 无需调整 1。

#### L4 报表影响

**P31 报表影响评估（materiality）**
- 原理：需调整错报总额与整体重要性水平（营业收入 43.45 亿 ×0.5% ≈ 2,170 万）比较，判断意见方向。
- 接口：`G04 P30 → material{金额, 意见方向}`。
- 传给：32 项需调整 1,083,925,000.00 + 4 项舞弊 + 披露重大缺失。
- 传样：错报规模远超重要性（约 50×）→ **意见方向：保留意见**（若拒绝调整且具广泛性则升级否定/无法表示）—— 审定重编为待办。

#### L5 结论与评测

**P32 结论与评测（evaluate）**
- 原理：检出结果与 `_ground_truth` 标准答案对拍，计算召回率与误报数。
- 接口：`G05 P31 + _ground_truth → verdict{recall, fp}`。
- 传给：42 项检出 vs 42 项标准答案（编号一一比对）。
- 传样：**召回 42/42 = 100.0%、误报 0 项、漏检 0 项** → 执行结果合格（演示层面）、意见方向保留。
