## 三、这批数据是怎么造的

生成脚本：`_tools/gen_client_data.py`（依赖 `_tools/coa.py`）

```bash
cd _tools
python gen_client_data.py       # 重新生成全套资料（幂等，结果确定）
python verify_client_data.py    # 审计组视角的交叉核对：只读 CSV，25 项全部通过
```

> `verify_client_data.py` **只读生成出来的 CSV 文件**，不引用生成器的内存变量。
> 也就是说：拿到这个文件夹的人，不依赖造数据的人，只读文件就能把各明细表与总账对上。
> 当前 **25 项核对全部通过**，见第五节。

### 三条设计主线

**1. 凭证驱动 —— "账不平"这种错报造不出来**

89 张凭证全部复式记账、逐张借贷相等。所以三个主体的试算平衡表**天然平衡**，
合并资产总计 = 负债合计 + 所有者权益合计是**推理结果**而不是配平结果。

> 这符合真实项目形态：客户交给你的账，**永远是平的**。真正的错报不在"账不平"，
> 而在单据、账龄、卡片、合同、决议里。

**2. 维度标签即附注 —— 附注不是第二套数据源**

每条分录行携带 `客户 / 供应商 / 关联方 / 产品 / 渠道 / 地区 / 税种 / 资产类别 /
使用部门 / 账龄 / 费用性质 / 现金流项目` 维度。资料包里的销售明细、账龄明细、
存货收发存、固资明细、费用明细、税费明细、薪酬明细，**全部由同一批分录按维度聚合**，
因此与试算平衡表逐项勾稽，不会出现"附注和主表对不上"。

**3. 折旧可由卡片复算**

固定资产卡片给出 `原值 / 转固日期 / 折旧年限 / 残值率`，审计师可独立重算：

```
年折旧额 = 原值 × (1 − 残值率) ÷ 折旧年限
当月增加当月不提，次月起计提；累计折旧封顶到"应计折旧总额"
```

10 张卡片里**只有 1 张（FA-P-008 高精度酒质检测设备）"账面本期折旧 ≠ 应有本期折旧"**。
