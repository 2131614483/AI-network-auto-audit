## 09:35–09:50 · 统一信息中枢设计

### 设计要点
- **核心取舍**：**不建六个页面**，先定一个统一条目模型 `InfoItem`（`item_id/kind/tenant/anchor/run_ref/occurred_at/status/evidence_sha256/provenance/relations`），六类信息面都是它的投影。
- **三类关系**：`derived_from`（事实链）/ `evidenced_by`（证据链）/ `used_in`（项目锚，待 `archive_links` 通电）。**关系算出来、不落表**（否则成第二真值源）。
- **五个工作台**：总览台 / 产物库 / 诊断台 / 文档与规则 / 进化台。
- **诊断台是目前唯一"完全缺失但素材最齐"的一台**：63 条 failed attempt 已带 `error_kind`，只需聚合查询，**零新表**。
- **自我进化 = 7 环闭环**：运行发生 → 事实投影 → 统计聚合 → 建议产生 → 人工决策 → 知识发布 → 回流生效。**实测 3 绿 / 2 黄 / 2 红**（环 4–5 半通、环 6–7 断）。
- **一条不可逾越的约束**：环 7 回流**只改概率分布**（候选排序/连线先验/提示上下文），不得新增能力或端口、不得放宽数据边界、不得绕过闸门。
- **新表数量 0**：全部落在"读聚合 + 已有表"。
- **落地顺序 P0–P4**：P0 诚实化三处误报（先"别撒谎"）→ P1 诊断台 → P2 产物库+复验 → P3 进化台 → P4 接通环 6/7（动能力，风险最高放最后）。
- **反模式**：六页面化、把 relations 存表、界面直连 DB、把"向量可用"做成装饰徽标、一键复现直接代执行、把断点藏起来。
