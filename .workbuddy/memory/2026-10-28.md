# 2026-10-28

## 发布/分发规划复核（21:50 起）

对 `docs/release-distribution-plan-20261028.md` 的方案做了仓库事实核对，补充以下实测数据：

- 无 `LICENSE`；`desktop/package.json` 只有 `electron-vite build`，**没有任何打包配置**（无 electron-builder / NSIS）；`web/` 只是 6KB app.js + 4.3KB index.html 的简化壳，不能当网页版。
- 插件子进程确认为 `packages/plugin_runtime/runner.py:272` 的 `[sys.executable, "-I", "-c", ...]` → 冻结单 exe 会破坏 `-I` 语义，**私有 Python 运行时（真 python.exe）比 PyInstaller 更稳**。
- 仓库体积：`.git` 已 114MB，跟踪 3575 文件；案例资产 `审计项目案例报告效果展示/` 66MB/2021 文件、`docs/` 25MB 已入库 → 公开仓库 clone 会 >100MB。**首发需决定案例资产是否分离到 Release 附件/独立仓库**。无单个 >5MB 的已跟踪文件。
- 工作区当前有 20+ 未提交修改（Phase 10 在办），打包基线必须先固定 commit。

结论：路线维持「一套核心 + 桌面/浏览器两入口」，但把最高风险前移为独立的可行性 spike（便携 PG16 + pgvector 的 Windows dll 匹配、插件子进程、干净目录 initdb），未过则该方案降级为「首启引导用户装 PG」。

**环境坑（会反复遇到）**：
1. 宿主环境有 `ELECTRON_RUN_AS_NODE=1` → 打出来的 exe 被当 Node 跑（`bad option`、无窗口）。测试要 `env -u`。
2. 同时存在 `HTTP_PROXY`/`http_proxy`，PowerShell `Env:` 与 `Start-Process` 直接抛"已添加项"。
3. `spawnSync(pg_ctl start)` 的管道被 postmaster 继承 → 永久阻塞，必须 `stdio:"ignore"`。
4. 安装版日志目录改 userData 后忘 mkdir → `appendFileSync` ENOENT → 整段 whenReady 静默失败。
5. electron-builder 清 `dist\win-unpacked` 触发 safe-delete 批量删除拦截，构建前先手工删。
6. npm 默认 registry 不可达（用 npmmirror）；electron-builder 装完缺 `balanced-match@4`，需 `--no-save` 补。

**未完成**：`/S` 静默安装在本机不生效（无交互桌面，只能人工点）；无签名/图标；端口固定 8010/54329；
