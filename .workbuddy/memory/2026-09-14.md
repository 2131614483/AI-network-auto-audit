**定位**：第三份数据集 = 同一批主体、**独立重造的账套**，24 处漏洞 + 5 项无害噪音。
与前两版的根本差别不是"漏洞更多"，而是**漏洞被藏起来了**：资料里零提示（无 ★、无"应有折旧"列、
无"核对结果"字样），每张表单独看都自洽，必须自己决定"查哪张表、比哪两个数、套哪条准则"。

**结构与文件**：
- `_tools/coa.py` 复用（科目表/记账/合并）；`case_design.py` 24 处漏洞的形式化定义
  （含 `tier` 能力分层、`stealth` 隐蔽手法、`why_hard`、`path` 检出路径）；
- `gen_hard_data.py` 生成器（116 张凭证 / 229 条分录 / 51 个资料文件）；
- `selfcheck.py` 隐蔽性扫描 + 基础勾稽基线；`make_docs.py` 生成标准答案与评估矩阵；
- `_ground_truth/` 预期发现清单（md/csv）+ AI胜任力评估矩阵 + 隐蔽性设计说明。

**能力分层（T1–T5，这是本数据集的核心设计）**：
| 层 | 含义 | 项数 | 编号 |
| T1 | 规则可检 | 3 | H14/H15/H16 |
| T2 | 跨表勾稽 | 5 | H01/H02/H03/H04/H07 |
| T3 | 比率与结构 | 3 | H05/H06/H08 |
| T4 | 准则与行业知识 | 8 | H09/H10/H11/H12/H13/H17/H18/H21 |

→ **T3–T5 共 16 项（67%）确定性规则查不出**；需调整错报 447,652,750 元。

**六种隐蔽手法**（写"难数据集"的方法论，可复用）：
1. **跨表错配**：每张表合计数都等于总账，差异只在两张不同来源表的分项之间（H01 采购发票 400M vs 入库明细 393.2M，差 6.8M 挂预付）。**关键：明细表的合计数必须与总账一致**，否则就退化成"低级对账题"。
2. **双向抵消**：同项目既有超提又有少提，**净额低于重要性**（H03 超提 6,032,500 / 少提 6,483,750 / 净 451,250 < 1,500,000）。
3. **金额稀释**：单笔均低于 SAD 75,000，要看累积（H14 12 笔 486,000）。
4. **形式合规掩盖实质**：账/单/票齐全，靠**读合同条款**（售后回购、代理结算）或**套新准则**（新租赁）发现（H09/H10/H13）。
5. **披露遗漏**：账全对，错在"没说的话"（H17–H21）；H21 更细——附注**已列**前五名客户金额，缺的是**判断性表述**。
6. **线索藏在非结构化文本**：担保写决议第四条、并购写办公会纪要、败诉写"上诉后确定"、关联方要**穿透两层股权**（董事配偶→投资管理公司→供应链公司）。

**实测验证**（三条都跑过）：
- 三主体试算平衡 0.00；合并 11,523,370,635.70 = 4,275,700,000.00 + 7,247,670,635.70；
- `selfcheck.py` 扫描 51 个文件 → **零提示性用语**；
- **6 条基础程序全部通过，0 检出**（试算平衡/合并平衡/账龄合计/存货收发存/固资卡片/应交税费）；
- 分析性程序可见信号：Q1 毛利率 42.86%（低于其余季 ~56.9%，H10）→ Q4 60.42%（较 Q3 +3.56pct，H05）；
  存货周转 409 天（上年 374）→ H06；销售费用率 6.96%（上年 7.50%）而收入 +12% → H08。

**给 AI 的评估口径**：总体召回率、**分层召回率**（看在哪一层断崖）、误报率、证据充分性、方向正确性
（H03 只报净额视为未检出）。结论档位：确定性程序只能查 3/24；AI 有望独立完成 T1–T4 = 19 项（79%）；
T5 5 项只能提供线索。设计靶心是**第三层「意识能力」**——前两层失败是能力不足，第三层失败是"不知道自己不知道"。

**踩坑（写生成器必读）**：
- **`cat >> file <<'EOF'` 追加过大时 shell 会截断报 `unexpected EOF`**，但文件可能已写成功 —— 事后必须校验 `ast.parse` + 实际运行，别只看退出码。
- **用 Python 做"按 `if __name__` 截断"极其危险**：`s.index('if __name__ == "__main__":')` 会命中**文件中间**的那一处（因为之前是 append 到末尾的），一次删掉了 5 个导出函数。截断前先备份或改用行号定位。**教训：批量文本手术要么带锚点精确替换，要么先复制一份。**
- 生成的 Markdown 里**不要用 `%` 格式化**：`|---|` 的 `%` 会让 `ValueError: unsupported format character '|'`。改用 `@@key@@` 占位符 + `.replace()`。
- **中文文本里混入 ASCII 双引号会破坏 Python 字符串**，且"引号个数为偶数"的检查抓不出来。写完脚本先 `ast.parse`，报错定位到具体行再改用「」。
- 分部/分季度的**成本与收入必须成对打 `src` 维度标记**：只给收入打、不给成本打，会让"季度毛利率"算成负偏差（内部销售被计入分子）。
- 内部交易量要够大，否则"应有结转额"会超过**可供销售**（期初+本期入库），出现负存货（S1 从 1,070M 调到 1,200M 才够）。
- 折旧函数三种情形缺一不可：满年 / 当年新增（当月不提次月起）/ **已提足封顶**。
- 基础勾稽基线脚本自己也会写错：账龄表列名是"期末余额(借正贷负)"、存货收发存的"财务账口径"**不含**存货跌价准备 1471 —— 基线误报会让人误判数据集有脏数据。
