# 下载并部署到其他电脑

当前优先在 [Gitee](https://gitee.com/hx2131614483/audit_network) 的 `codex/gitee-deployment-debug` 分支调试；具体步骤见 [Gitee 调试说明](gitee-debug-20261029.md)。以下 Windows 安装包流程为发行交付目标，以实际发布附件和验收记录为准。

目标平台：Windows x64。首要交付为包含私有 Python、PostgreSQL 16/pgvector、API 和 Worker 的安装包；源码是第二种部署方式。本地浏览器仍为简化入口，完整工作台在 Electron 中。

## 普通用户：Windows 安装包

1. 在项目 GitHub Releases 下载对应版本的 `AuditNetwork-<version>-win-x64-Setup.exe`、`SHA256SUMS.txt` 和发布说明。以 Release 实际存在的附件为准，仓库中的历史测试包记录不代表该附件已经发布。
2. 用 `certutil -hashfile <安装包完整路径> SHA256` 比对摘要，按安装器提示安装到当前用户可写目录。
3. 启动后明确选择“初始化工作区”。程序创建自己的本机数据库与独立凭据；取消不建库。完成后进入工作台。
4. 在“AI 设置”保存模型提供方、模型、接口地址与自己的 API Key，普通工作区选择“外接 AI API”。API Key 不随安装包分发。
5. 在“组网规划”点击“配置完成，启用本机规划”，在本机确认框核对模型和端点后确认。系统记录策略裁决，只给当前工作区、当前配置授予有限的 plan_only 能力，并启动专用规划后台。换模型配置后重新确认。
6. 导入自己的资料，登记任务输入，提交规划。资料、能力、权限或模型不可用时显示缺口；评估通过代表静态方案通过，不代表插件已执行或审计结果已验证。

默认 Debug 继续保留，供当前 Codex 会话逐次回填的合成联调用途；要求独立本机测试数据库。它不会为其他电脑提供免费的无人值守 AI 服务。

程序资源留在安装目录；数据库、配置、日志、工件和维护历史留在当前用户目录。常规退出会停止本程序管理的后台；关闭窗口后持续运行的托盘功能目前未提供。卸载默认保留工作区。

## 升级与故障

- 普通启动不自动迁移。版本不匹配时，明确确认后先生成数据库备份并完整读取验证，再迁移到安装包声明的版本；没有策略授权、版本未知或备份失败时停止。
- 维护记录为 `data/maintenance/history.jsonl`，初始化后关联到数据库策略审计。失败或状态未知时保留工作区、备份和历史，不删除目录后重试。
- 老预览工作区若没有新的维护策略会被拒绝升级；不能通过另一次确认绕过拒绝。先备份，由管理员在测试副本核对与配置对应权限。
- 数据库 dump 还不是完整工作区备份。跨电脑迁移已有业务资料时还需恢复工件、角色、授权与配置；完整权限及工件恢复仍在验收，首发不提供“一键迁移旧工作区”的承诺。
- 当前安装包未代码签名，系统可能提示未知发布者；摘要校验用于核对发布文件。不要把校验摘要当成签名。

## 技术用户：源码部署

从 Release 的源码包或仓库指定 tag 获取源码，按 [源码安装](install-from-source.md) 创建虚拟环境、角色和空库，显式执行迁移/初始化，再分别启动 API 与 Worker。应用账号必须为 NOSUPERUSER / NOBYPASSRLS，不能用迁移账号跑应用。

源码桌面使用 `npm ci --prefix desktop` 和 `npm --prefix desktop run dev`；仅浏览器简化入口可不装 Node。仓库根目录的 `.env`、`.data` 和任何真实业务资料不应重新上传 GitHub。

Docker 文件属于可选环境适配器，尚未在本机验证；在线公网部署尚无完整登录到租户的可信映射。不要将当前 Docker/简化网页描述为与桌面等价的正式在线版。

## 发行验证范围

发布前分别记录源码检查、随包运行时新工作区初始化/再次启动、规划配置授权、应用角色权限和原生安装交互。当前新增的运行时测试脚本为 `scripts/verify-release-runtime.cjs`：只用独立合成工作区，保留报告并正常停止自己的数据库，不连接真实模型。

正式附件的版本、提交、摘要和测试证据应来自同一次构建。发布前状态详见 [开发状态](status.md)，不能将历史原包的 SHA256 用于新包。
