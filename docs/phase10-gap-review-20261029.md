# Phase 10 疏漏复核与继续实施顺序

日期：2026-10-29，Asia/Shanghai。依据：AIchatroom AG-08 至 AG-12、当前源码与本轮定向测试。AG-07 属于 LocalStock 项目，不纳入本项目验收。查看时最新留言为 AG-12，没有发现其他 AI 的后续回复；交接中的建议不自动成为新的阶段授权。

## 当前结论

核心规划链路已有实现和验证：审计知识主脑 → 审计任务说明 → 插件目录/关系与历史经验 → 候选方案 → 硬检查及独立评审 → 按缺口补查/修订 → plan_only 会话与追加历史。当前缺口主要集中在首次使用、后台可靠运行、维护治理和可复现交付。继续增加 Agent 数量不能代替这些验收。

Phase 10 保持进行中。accepted 代表静态方案与评估通过，不代表执行成功或得到真实审计结果；本轮不升级开发库、不启用开发库策略、不调用外部模型、不执行新方案。

## 下一步逐批实施

所有批次先补契约/验收用例，再改实现；每批留证据、更新状态。批次通过才进入下一批，Phase 10 全部验收前不标完成。

后续实现沿用现有 Python/FastAPI 后端、React/TypeScript 工作台、Electron 桌面壳及 PostgreSQL 16/pgvector；借鉴的功能接入现有契约、策略网关和服务层。桌面与浏览器共用业务页面，通过平台适配处理本机能力；该共用改造仍待实施。

1. **先修可定位缺陷（G04/G07）。** 最小变更处理未知租户、子进程启动/退出与日志可用性；保留策略拒绝语义和原始失败历史。通过针对性失败回归、桌面检查及相关 API/PG 测试。
2. **打通首次规划与后台（G03/G05/G08）。** 先做就绪检查及合成测试工作区的引导；把上传工件、输入绑定、模式说明、领取/等待状态连起来。保持 Debug 当前会话逐次回填与 external 本机可控端点两条验收；并发、断线、重启后不重复写、不冒用旧评审、不执行插件。
3. **补维护与恢复（G01/G02/G06）。** 在独立本机库实现并测试引导策略/维护审计；Docker 保持可选适配器。完成旧版本升级、迁移失败、断电/重启、权限及工件恢复。普通启动始终不自动升级。
4. **做 Phase 10 完整验收（G09 + 既有验收项）。** 合成审计问题覆盖知识召回、主脑修订、插件替换、失败历史、来源变化、预算终止、模型错误、队列恢复；跑全部阶段测试并列明跳过原因。真实资料或真实云端调用不在本轮测试范围，不能伪称通过；扩展验证需先明确与当前约束一致的范围。
5. **再收口 Windows 与本地浏览器交付（G10/G11/G12）。** 先形成可复现测试包并完成普通权限、中文/空格路径、全新安装、第二次启动、升级和卸载保留资料验收。浏览器复用完整工作台和受控接口。既有原生 GUI 验收仍是缺项。
6. **在线网页作为后续独立阶段。** 登录、服务端租户、存储、密钥与额度隔离完成后再谈公开部署；目前只保留规划。

建议后续 AI 分工：原验收角色复核第 2/4 批；打包角色负责第 3/5 批的运行时和交付；代码修复角色先完成第 1 批。此为建议和异步留言，本轮未创建或派发子代理任务，不宣称其他 AI 已接受。
