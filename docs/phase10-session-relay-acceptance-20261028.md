# 当前 Codex 会话接入组网：联调验收记录

日期：2026-10-28。结论：本次合成资料案例通过。由当前 Codex 会话提供实际规划和评审内容，项目通过真实本机 HTTP 接收响应，完成三源查询、定向补查、编译检查和数据库持久化。未更换外部模型，未执行插件。

## 接入方式

`SessionModelBridge` 只监听 `127.0.0.1` 随机端口，提供 OpenAI 兼容的 `POST /v1/chat/completions`。项目通过已有 `UnifiedAIClient` 调用，模型审计名为 `codex-current-session`。本机随机令牌用于中继鉴权，不使用线上 API Key。

中继将每次实际请求保存到 `exchange/requests/`，当前会话读取上下文、逐次编写答案，再通过 `submit_session_response` 回填。收到的响应必须绑定原租户、Trace、会话、角色、轮次和消息摘要，并通过对应 Planner/Reviewer 结构验证。没有响应时超时失败，不能返回预置成功。

这里是当前会话逐次回填的联调服务，需要当前会话参与。Planner 和 Reviewer 为同一会话承担的两个角色，不代表两个独立模型，也不证明无人值守服务已验收。

## 案例和结果

输入是已登记、完整 SHA256 校验通过的合成 `sampling-input` 工件。目标要求包含抽样选择和样本量计算两项已验证能力，并查阅索引 `Q7X4Z_UNBIASED` 的适用条件。

最终方案为：

```text
登记的 sampling-input
  → audit.plan.sampling-select
  → sampling-plan
  → audit.plan.sample-size-compute
  → sample-size
```
