# 组网测试 · 三种难度（2026-09-24）

对三份审计案例数据集（对照组 / 实验组 / 高难度）各跑一遍该案例的**确定性审计程序网**，
记录检出、误报与基线。全部只读原始资料、无网络、无 LLM。

| 难度 | 数据集 | 规模 | 组网程序 | 检出 | 误报 | 基线 |
|---|---|---|---|---|---|---|
| 对照（基础） | `黔岭酒业2025年度财务报表审计` | 10 处漏洞，**每处带 ★ 标记与提示列** | `_tools/audit_engine.py`（T1–T10 实质性程序 + 勾稽复算总览） | **10 处**，与设计口径一致 | — | — |
| 实验组 | `..._实验组` | 42 处漏洞，**有"应提 X / 已提 Y"明确对照** | `_tools/detect_issues.py`（28 条确定性程序） | **42/42 = 100%** | **0** | — |
| 高难度 | `..._实验组_高难度` | 24 处漏洞 + 5 项噪音，**零提示** | `_tools/audit_verify_hard.py`（逐项复算 + PN1–PN5 噪音核对） | **24/24** | **0**；噪音 5/5 正确排除 | **基础勾稽 0/24** |

**一句话结论**：难度确实是递增的 —— 基础版靠标记就能找；实验组靠规则对照能全召回；
高难度**零提示、教科书式程序一处也查不出（0/24）**，而完整组网能全命中且不误报噪音。

## 一、必读：这测的是什么，不是什么

三份数据集的"预期发现清单"是**出题人的答案**，检测程序按它打分。所以上面的
42/42、24/24 说明的是：

* ✅ **数据集自洽**：答案清单里写的每一处漏洞，都**确实能从原始 CSV 里确定性复算出来**（不是写在纸上的设定）；
* ✅ **难度分层成立**：基础勾稽程序在高难度数据集上检出 **0/24**，说明这批数据真的区分"会跑程序"与"会做判断"；
* ❌ **不等于"AI 找到了 42/42"** —— 这是**带答案的自检**。要测 AI 的真实能力，必须让它**在看不到答案清单的前提下**跑一遍再对拍。这一步本轮**未做**（需要接入模型并设计盲测流程）。

把"自检"说成"AI 评测"是最容易发生的夸大，这里先把口径钉死。

## 二、逐难度结果

### 2.1 对照组（基础）：10 处漏洞，全部带 ★ 标记

```
_tools/audit_engine.py   →  汇总：调整分录 7 组，涉及金额合计（绝对值）293,450,000.00
                            审定净利润：1,322,766,875.00（未审 1,431,111,875.00）
                            结论：错报合计超过财务报表整体重要性水平，审计意见方向为保留意见

_tools/verify_client_data.py →  核对项 25 项，通过 25 项，未通过 0 项
```

- 引擎**只读** `01_被审计单位提供资料/` 下的 CSV/MD，不引用生成器内存，每个数字都是对原始文件的实测复算。
- 产出的底稿与发现清单落在 `04_实质性程序/`（11 份）、`06_发现与调整/`（2 份）、`05_报表编制/`（1 份）。
- 交叉核对 25/25 通过，说明这批资料**可被独立复核**——审计师拿到文件夹不依赖造数据的人也能对上账。

### 2.2 实验组：42 处漏洞，28 条程序全召回

```
【召回】预期 42 项，检出 42 项，召回率 100.0%
【误报】0 项（无）
```

28 条程序逐条命中，覆盖收入截止（4 条）、关联方穿透（4 条）、披露完整性（7 条）、
费用真实性（4 条）、坏账重算、存货监盘、固定资产折旧重算、政府补助分类、研发费用归集等。

数据特征：每处漏洞都带**明确对照**（"应提 X / 已提 Y"），所以这一档测的是
**规则匹配召回率**——只要程序写得对，理论上应当全召回。

### 2.3 高难度：24 处漏洞 + 5 项噪音，零提示

```
_tools/audit_verify_hard.py  →  命中 24/24
                                噪音：N01–N05 全部 [通过]（正确排除，不误报）
                                证据写入 _tools/audit_evidence.json

_tools/selfcheck.py          →  隐蔽性扫描：✓ 未发现任何提示性用语
                                基础勾稽基线：6 条教科书式程序全部通过，对 24 处漏洞检出 0

_tools/case_integrity.py     →  源文件 51 个；CSV 业务键普查 35 张；失败 0 张；报告证据绑定 通过
```

**能力分层（为什么 0/24 不是程序写得差）**：

| 层 | 含义 | 项数 |
|---|---|---|
| T1 规则可检 | 确定性脚本能查 | 3 |
| T2 跨表勾稽 | 单表自洽，须对两张以上表勾稽 | 5 |
| T3 比率与结构 | 须做趋势/比率分析 | 3 |
| T4 准则与行业知识 | 须懂白酒消费税双计征、新租赁准则、售后回购实质等 | 8 |
| T5 职业判断与沟通 | 须访谈/函证/判断意图 | 5 |

**T3–T5 合计 16 项（67%）需要分析或判断**。基础程序之所以 0 检出，是因为：

- 账本来就是平的（凭证逐张借贷相等）；
- 明细表的**合计数**与总账一致，差异藏在**分项**里；
- 大部分问题不是数字对不上，而是数字背后的**处理方式**不对。

数据还设计了 **5 项无害噪音**（关联交易、会计估计变更、季节性波动、募投一致、跌价转回），
形状与漏洞高度相似 —— 一见到这些关键词就报的模型会在这里误报。本次 5/5 全部正确排除。

## 三、可复现性

**整套测试逐字节可复现**：三轮全部跑完后，`git status` 在案例目录下**只有 1 个文件变化**：

```
M 黔岭酒业2025年度财务报表审计/_audit_digest.json
```

差异**只有一行**，且与审计结论无关：

```diff
- "case_root": "D:\\pythonpro\\audit_network\\审计项目案例\\黔岭酒业2025年度财务报表审计"
+ "case_root": "D:\\pythonpro\\audit_network\\审计项目案例报告效果展示\\黔岭酒业2025年度财务报表审计"
```

即案例目录曾从 `审计项目案例/` 改名到 `审计项目案例报告效果展示/`，而该产物记录的是**生成时的路径**。
发现、金额、分录、意见方向**逐字节一致**。

高难度的 `audit_evidence.json`、`source_integrity.json` 与实验组的 `检出验证报告.md`
重跑后**无任何 git 变化**——即完整复现。

> **顺带发现（未处理）**：`_audit_digest.json` 里的 `case_root` 是过期路径。它是产物里唯一记录绝对路径的地方，
> 若被下游按该字段寻址会失效。修法是让引擎按**相对案例目录**记录，而不是本机绝对路径 —— 涉及改动引擎，本轮未动。

## 五、下一步建议（按价值排序）

1. **盲测**：去掉答案清单，让 AI 在同一份高难度资料上产出一份发现清单，再与 `预期发现清单.csv` 对拍 ——
   这才是真正的 AI 胜任力评测，也是这批数据被造出来的初衷（`_ground_truth/AI胜任力评估矩阵.md` 已经写好了评分口径）。
2. **接入本项目组网**：把案例 CSV 适配到插件契约（`ledger` / `audit-quality-candidates` 等），
   用项目的 AI 组网（`AiPlanner` + `start_plan_run`）跑一遍，让结果落进运行账本、证据包与图谱经验层 ——
   这样三份案例就成了项目自身的端到端回归数据，而不只是案例自带的脚本。
3. **修 `case_root` 绝对路径**（第三节），改成相对路径或去掉。
