# Phase 10：多源协作规划的首批实现

日期：2026-10-28。状态：核心实现、离线验收、桌面组件浏览器走查和当前 Codex 会话 API 中继联调已通过；其他模型效果与长期后台运行待验收，整个 Phase 不标记完成。

同日补齐审计主脑交接层：审计域默认先查知识、形成审计任务说明，再进入插件编排。最新实现与实际验收见 [审计主脑交接验收](phase10-audit-brain-acceptance-20261028.md)；此前的四次 Planner/Reviewer 联调记录保留为前一版证据。

同日保留两种正式接入模式：桌面“AI 设置 → AI 组网接入模式”选择 Debug 当前会话回填或外接 AI API。默认 Debug，模式只用于新的协作规划会话；旧的终态结果保留。实现与本次证据见 [两种模式验收](phase10-model-modes-20261028.md)。

## 已实现的路径

审计域：工作台提交目标与期望产物 → 持久化 plan-only 会话 → 专用消费者领取 → 审计知识检索 → AuditBrain 形成目标/风险/程序/证据要求/验收标准 → 依据不足时先补知识 → 任务说明检查通过 → 查询插件关系及历史经验 → Planner 选择真实插件、连线并映射审计程序 → 权威目录展开契约与硬检查 → Reviewer 逐目标、逐程序评估 → 按缺口退回主脑或修订插件组合 → 核验输入和证据新鲜度 → 保存方案或缺口。其他业务域保留原三源协作流程。

模型不能直接访问数据库、注册插件、修改目标/预算或授权执行。主脑只交接审计任务说明，Planner 只选择插件和程序映射，Reviewer 单独评估；三类 Scout 和 Coordinator 是受控代码角色。当前会话中继由同一会话承担三个角色，分别调用，不声称是三个独立模型投票。

### 来源

- 图谱：当前有效节点及内部关系，每项保留版本、关系和事实摘要；每节点最多 8 条关系，跨空间 bridge_edges 暂未纳入，返回值明确注明范围。
- 历史：同时读取 CW3 node_attempts 与 M6 execution_runs/ledger，保留失败、输入输出和具体版本；历史成功不会成为执行权限。
- 知识：纯关键词正文检索，保留文档/chunk/版本/来源及全文摘要；当前正文来源保守标记为参考，不自动授予规范性权威。不构造默认 embedding 客户端，不向云端发送内容。
- 业务输入：只接受当前租户已登记 Artifact ID；检查允许根、完整 SHA256、大小与可读性，不接受模型给出的路径、URL、UNC 或命令。

同一运行在图谱经验、历史和知识总结中出现时，统一血缘 `db://runs/{uuid}` 并在规划上下文按共享来源分组。它们不是三份独立佐证。

### 评估与恢复

- 硬检查覆盖目标产物、真实插件/端口绑定、业务端口语义、必填输入、显式预算、参数类型及适配器的实际转换契约。
- 每个节点有引用，每个目标有独立评审；Reviewer 阻断项不能由 Planner 覆盖。评审绑定目标、候选和证据三个摘要，编译摘要另绑定输入工件快照。
- 审计任务说明绑定原目标与知识快照；候选逐程序映射节点，评审另绑定任务说明摘要并逐程序核验，编译摘要也包含该说明。业务修订先于随后提出的插件来源查询。
- 接受前重读证据有效性、复核输入；目录、实现、端口 schema 与参数声明也冻结并核对。变化时刷新证据或撤销旧资格；最终目录变更/不可读时同时清除通过标记和可用计划。
- 会话有幂等键、请求摘要、租约与 fencing。事件只能追加；checkpoint 与事件原子提交。通过后、终态提交前崩溃，可重新核验并恢复结果，不必重调模型。
- 有轮数、来源查询、模型调用、证据字符、图节点和时间预算；重复无进展时结束。失败来源返回的内容不会并入证据集。

`accepted` 仅表示方案的静态检查和独立评估通过。此阶段没有将它提交到插件执行器，不代表已产生并验收真实业务结果。

## 入口

桌面“组网规划”页上方新增“多源协作规划”：填写任务目标，选择可检查的期望产物；输入绑定每行填写 `端口 ID,已登记工件 UUID`。提交后可查看来源证据、轮次与评审，或点击“立即运行规划”。原有意图、蓝图和计划视图保留。

HTTP 入口均要求 `X-Tenant-Id`，Trace 由现有中间件建立：

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/topology/planning/sessions` | 按请求幂等键创建会话 |
| `GET /api/v1/topology/planning/sessions` | 当前租户会话列表 |
| `GET /api/v1/topology/planning/sessions/{id}` | 详情、追加事件与结果 |
| `POST /api/v1/topology/planning/sessions/{id}/process` | 显式运行规划；并发领取互斥，终态可回读 |
| `GET /api/v1/topology/planning/catalog?domain=audit` | 当前可验证绑定及输入输出，供选择期望产物 |

会话写入、逐源读取、模型调用均实时读取有效策略并记录 `policy.tool_calls/decisions`。事件记录每次裁决引用，最终结果关联策略快照裁决。链路授权不能替代来源读取授权。

## 开发环境启用顺序

1. 使用本机迁移账号连接，**显式**运行 `python -m alembic upgrade 0069_collaborative_planning`。应用启动不会自动升级；运行前确认 `DATABASE_URL` 指向拟升级的本机库。
2. 在现有策略治理流程中审核并启用 `local-collaborative-planning`。迁移将它种为 **inactive**；其中只有 plan-only 写入、来源读取、模型调用七项精确能力，没有插件执行、网络或泛化 AUTO 授权。本次没有激活开发库策略。
3. 在桌面 AI 设置保存 `planning_mode=debug` 或 `external`（对应 `AI_PLANNING_MODE`）。Debug 需服务端显式设置 `AUDIT_COLLABORATIVE_DEBUG_SYNTHETIC=1`，数据库须为 loopback 主机且库名以 `_test` 结尾或 `test_` 开头。外接模式使用已保存的 `AI_PROVIDER`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 等统一配置；本地 Ollama 也是外接于本软件的模型 API 选项。旧 `AUDIT_COLLABORATIVE_MODEL_URL/MODEL` 不再选择默认协作通道。不会自动下载模型或失败后换模。
4. 如业务输入不在项目 `.data`，由受信的服务端配置 `AUDIT_COLLABORATIVE_READ_ROOTS` 为 JSON 路径数组。该值不接受模型或浏览器修改。
5. 使用既有启动流程重启更新后的 API/桌面服务。页面可以显式运行已提交会话；若需自动消费，在本机 Worker 环境设置 `AUDIT_NETWORK_COLLABORATIVE_PLANNING=1`，再启动既有 Worker。

也可以单独启动队列消费者（`DATABASE_URL` 使用本机应用账号连接）：

```powershell
.\.venv\Scripts\python.exe -m apps.worker.collaborative
```

专用消费者不与 Outbox/富媒体共用串行工作循环，模型等待不会阻塞主 Worker 心跳。重启靠数据库会话与租约恢复，页面退出不丢请求。

当前“立即运行规划”请求要等待本轮规划返回；后台消费者则可在页面退出后继续。没有运行中的取消按钮；当前阶段通过预算和租约收口，状态契约中的 cancelled 为保留状态，未提供取消路由。
