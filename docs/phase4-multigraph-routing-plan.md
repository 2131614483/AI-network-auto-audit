# Phase 4：多级、多集群知识图谱路由与治理

## 目的

把现有的单空间图谱升级为可控的多图谱中枢：图谱内部可以高关联，图谱之间只能经明确登记的少量桥接关系访问。系统先在控制面收敛候选空间，再在一个或少量业务图中进行预算查询，避免海量关系导致检索爆炸。

## 五层与物理边界

| 层级 | 角色 | 允许承载 | 不允许承载 |
| --- | --- | --- | --- |
| L0 | 集群/调度 | 集群、租户路由、健康摘要 | 证据正文、任意业务事实 |
| L1 | 蓝图 | 工作流蓝图、依赖声明 | 大规模业务实体 |
| L2 | 能力 | 插件能力契约、输入输出约束 | 插件可执行入口 |
| L3 | 业务域 | 审计、量化、AIOps 等领域实体和关系 | 跨域任意边 |
| L4 | 运行/证据 | 来源、版本、运行投影、证据回链 | 控制平面全图复制 |

图空间保存明确 profile（层级、角色、集群键）；内部边只能留在同一空间。跨空间只能经 `artifact_ref`、`capability_contract`、`released_graph_ref`、`health_signal` 四类已登记桥接；数据库触发器同时验证端点、租户、空间和登记规则。

## 路由预算

每次查询必须传入并返回预算：图空间数、内部跳数、桥接跳数、前沿宽度、节点/边上限、延迟上限、最小置信度、可选关系与空间白名单。响应必含实际访问空间与截断原因，绝不以“全量结果”伪装截断查询。

## 生命周期与冲突

- 节点更新、回收、恢复和回滚写入不可变历史版本；回滚只恢复该节点已记录的旧快照，不删除证据或历史。
- 删除是进入回收站；恢复是显式操作。
- 冲突保留来源主张，先进入冲突收件箱；后续由受策略控制的人工操作决定处理，不能由路由器自动抹除。

## 验收

1. 契约拒绝任意桥接和无预算路由。
2. PostgreSQL 强制拒绝未登记、跨租户、端点不匹配的桥接。
3. 两个 L3 图加一个 L2 桥接的路由只在预算内经过许可桥；耗尽预算时返回可解释截断。
4. 节点更新、回收、恢复和版本回滚可验证；历史不硬删除。
5. Golden Query 工具只操作 `audit_network_test`，支持 10 万节点/100 万边参数，常规回归采用较小合成样本。
6. Electron 图谱工作台显示层级/集群、桥接计数、路由预算和截断状态；所有读取仍经策略网关。

本阶段不进行文档/LLM 自动抽图、不启动插件、不执行外部网络或生产自动化。
