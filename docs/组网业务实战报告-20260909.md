**过程说明（诚实声明）**：



1. 云端真实调用成功（HTTP 200，模型推理并返回草稿），3 次修订循环均被**编译闸门拒绝**—— 缺口：`port 'audit-quality-candidates' of node ledger-a has bad cardinality`（AI 草稿中 ledger-a 节点输出端口基数与能力契约不符）。

2. 闸门拒绝后**显式降级**为确定性模板计划（`plan_key=demo-fc8ad6a7`），**不携带不合规草稿继续执行**（fail-closed）。

3. 这是设计内的安全属性：**AI 输出不可信时，闸门拦截 + 显式降级 + 业务链路照跑**，面向 24×7 自动运行不会因 AI 抖动中断。

4. 云端模型对 planner 编译契约（端口 cardinality）的合规率当前不稳定（连续多次运行一致表现为 gap\_report）；小 JSON 请求稳定通过，大组网草稿不稳。已在本报告「已知限制」中记录。

> 注意：
>
> `status=fallback_template`
>
>  表示
>
> **执行计划来自确定性模板**
>
> ，不是云端草稿；云端调用本身真实发生并有缺口报告留痕。这与「不用 ollama、用云端」的要求不冲突 ——AI 组网入口为云端模型，闸门按契约拒绝其不合规草稿。

## 13. 已知限制（诚实声明）



1. **云端模型草稿合规率不稳定**：`meituan/LongCat-2.0:free` 对 planner 编译契约（端口 cardinality）连续多次输出不合规草稿，被闸门拒绝后走显式降级模板。本次业务结论基于**确定性模板计划**，云端真实推理仅到「缺口报告」层。若需云端草稿直接驱动，需换用契约理解更强的模型或调优 planner prompt。

2. **evidence\_refs 溯源缺口**：回测评估的 `evidence_refs` 含 `ledger-quality:unknown`（adapter 从 candidates 契约取 quality\_hash 未命中，取到 unknown）；根因是 `audit-quality-candidates` 契约无 `quality_hash` 字段（有 `rule_pack_sha256`），属现有 adapter 的已知口径，不影响候选内容本身。

3. **测试库目录污染**：`capability_catalog_from_db` 返回 272 项含 `audit.it-*` 历史测试残留，脚本按业务域过滤后才交给 AI；生产库无此问题（业务蓝图 status 合规）。

4. **模拟口径**：回测为 simulated-only（non-production），`promotion.recommendation=hold` 表示不做生产变更 —— 符合 Phase 9「不运行生产修复」边界。
