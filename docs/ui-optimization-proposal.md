# 审计智能中枢 · 桌面端 UI 优化方案

> 评估时间：2026-09-10
> 评估方式：启动本机控制平面（API 8010 + Worker + PostgreSQL 16）后运行 Electron dev，逐页实拍；结合 `desktop/src` 全部组件源码与 `globals.css` 设计系统交叉核对。
> 评估环境：2560×1440 物理 / 2048×1152 逻辑（125% 缩放），深色主题，租户 local-dev，控制平面已连接。

## 一、现状评估

### 做得好的地方（保留）
- **设计系统规范**：`:root` 有完整的颜色/层级/语义色 CSS 变量（`--bg/--bg-panel/--accent/--up/--down`），深色主题统一，表格、卡片、Tag 风格一致。
- **安全边界表达清晰**：每页副标题都写明"读取经策略网关 / 写入幂等带租户 Trace"，Policy Gateway 标签贯穿，符合产品定位。
- **AI 画布助手底子好**：`AIChatPanel` 已实现停靠/浮动/最大化/最小化胶囊**四种窗口模式**、可拖拽、可拉伸、SSE 阶段流（召回→生成→校验→编译）实时可见、可取消——这正是核心诉求，已具备。
- **Run 画布是真数据投影**：节点=真实 attempt、边=数据流，支持无限画布缩放/平移、节点检查器、草稿拖拽编辑，技术栈正确。

## 二、设计原则（优化时统一遵守）

1. **审计人员优先，中文为主**：界面文案、节点标题、状态全部中文；技术标识（plugin_id/trace_id）作为次要等宽字体信息折叠展示。
2. **状态一眼可读**：运行/组网是核心，成功绿、失败红、运行中蓝、等待灰、退避黄的语义色在列表、画布、徽标三处保持一致。
3. **密度可调、默认紧凑**：审计是长时间盯屏作业，默认提高信息密度，提供"舒适/紧凑"切换。
4. **主工作区最大化**：Run 画布是主战场，侧栏与 AI 面板都应可彻底收起，把屏幕让给图。
5. **不破坏安全模型**：所有 UI 调整只改呈现层，IPC 边界、策略门、租户/Trace 透传一行不动。

## 三、P0 · 布局硬伤（建议最先修）

### 3.1 顶部 toolbar 截断
**根因**（`App.tsx` 1829 行 + `globals.css` 44-59 行）：toolbar 用 `display:flex` 但中间 `index-bar` 设了 `flex:1`，右侧 `tenant-switch` 固定 310px、`window-controls`+`zoom-controls` 又占 ~250px，brand 还占 224px，总和在 125% 缩放 + 中文标签下溢出。

**改法**：
- brand 收窄到 `min-width: 160px`，英文副标 `DESKTOP CONTROL PLANE` 在 <1400px 时隐藏（`@media`）。
- `index-bar` 三个状态块允许收缩：`min-width` 从 136 降到 104，「策略模式/连接状态」改为"图标+短词"（如 `● 已连接`），详情进 tooltip。
- `tenant-switch` 从 310 降到 260；把「日志」按钮收进窗口控制左侧的图标按钮组（只留图标，tooltip 出文字）。
- 加 `flex-wrap: nowrap; min-width:0` 并对每个区块加 `overflow:hidden; text-overflow:ellipsis`，保证任何宽度都不出现横向裁切。

### 3.2 Run 画布三栏溢出与空洞
**根因**（`globals.css` 233-294 行）：`.runcanvas-split` 三栏固定并排，`.aichat` docked 恒为 330px；未选 run 时中间画布只有一行空态文字，AI 面板却仍占 330px，把总宽撑过视口。

**改法**：
- 三栏改为**可折叠栅格**：运行历史、AI 助手各加「收起为细竖条（48px，只留图标）」按钮，状态记忆到 localStorage；画布 `flex:1; min-width:0`。
- 未选 run 的空状态升级为**居中引导卡片**（不是左上角一行字）：图标 + "选择左侧一次运行，或新建 AI 组网" + 两个按钮（查看最近成功 run / 新建 AI 组网），消除中段黑洞。
- AI 助手 docked 宽度从固定 330 改为可拖拽调宽（280–460），默认 340；浮动/最大化模式逻辑不变。
- 三栏总宽超出时优先自动收起 AI 面板为胶囊（复用已有 minimized 模式），而不是把它挤出屏幕。

## 四、P1 · Run 画布（核心工作区）体验

### 4.1 运行历史队列（`RunsPanel.tsx`）
- **顶部加工具行**：状态筛选 Tab（全部/运行中/成功/失败，带计数）+ plan_key 关键字搜索框 + 刷新。
- **失败 run 治理**：调试期产生的 failed run 提供"仅看本 plan_key"开关与"清空失败投影（仅视图过滤，不删库，符合证据不硬删约束）"。
- **卡片补信息**：在现有 id/status/plan/attempts/时间基础上，补**耗时**（finished-started）、**节点进度条**（attempt_succeeded/total 的迷你进度条，失败段标红），成功/失败用左侧 3px 色条强化。
- **默认选中最近一次 succeeded 的 run**，进入画布即见图，不用手动点。
- run id 目前显示裸 8 位 hash，建议格式 `#${前6位}` + 相对时间（"3 分钟前"），完整 id/时间进 tooltip。

### 4.2 画布节点与连线（`RunCanvas.tsx`）
- **节点中文化 + 双行结构**：第一行显示插件中文名（从 protocol 的中文 title 取，建一张 plugin_id→中文名映射，正好 100 个插件已有分组），第二行等宽小字显示 plugin_id 末段；状态从英文改中文徽标（等待/运行中/成功/失败/退避/已取消，`STATUS_LABEL` 已有，补到节点主显位置）。
- **阶段泳道/分层底色**：100 插件本就分支撑/业务 8 阶段/治理三层，按 layer 给浅底色带或纵向泳道列，组网时一眼看出"立项→…→治理"走向，替代现在所有节点同色矩形。
- **节点状态用整卡语义**：成功卡左缘绿条、失败卡淡红底+错误图标、运行中加流动描边动画；现在只有右上角 5px 小圆点，100 节点时几乎看不见。
- **失败节点优先**：提供"定位下一个失败节点"按钮，自动平移居中并打开检查器；100/100 时显示"全部成功"绶带。
- **边标签**：现在边中点显示 `source_port → target_port`（英文契约名），保留但加中文别名 tooltip；边按数据契约类型着色（校验类/文档类/指标类）。
- **迷你地图（minimap）**：100 节点缩放 24% 时需要右下角缩略导航图，点击/拖动跳转。
- **工具条补齐**：现有「复位/最大化/缩放%」，增加「适应屏幕」「按阶段分层布局/力导布局切换」「导出 PNG/SVG」「仅看失败路径」。
- 节点宽 220 固定改为按内容自适应（200–260），长 plugin_id 不再溢出。

### 4.3 节点检查器
- 检查器现在浮在画布左上，信息为英文 dl 列表。改为右侧抽屉式：中文标题、状态时间线、输入/输出端口契约（中文名+类型图标）、产物文件路径加"在文件夹中显示"按钮、error_message 失败时红色高亮块 + 「复制 trace_id」。

## 五、P1 · AI 画布助手（`AIChatPanel.tsx`，已具备骨架，做精）

- **阶段流可视化升级**：现在是逐行文字（✓/✗/转圈）。改为**顶部 4 步进度条**（召回能力→模型草稿→白名单校验→确定性编译），失败步红色并可展开 issues；下方消息流只保留对话，减少重复。
- **思考/输出分区**：用户明确要"实时输出和思考内容"——把 stage 细节（命中多少能力、第几轮修订、被哪条校验打回）收进可折叠的"执行细节"区，默认展开当前步、完成后自动折叠，避免长列表淹没对话。
- **草稿卡片增强**：draft 消息现在显示"N 节点/N 边/修订轮次 + 应用到画布"。补**节点中文清单预览**（可滚动）、与"当前画布"的 diff 摘要（新增/删除/改连了几个节点），再决定是否应用。
- **运行中调整闭环**：应用草稿后进入 draft 模式，画布顶部出现一条**草稿模式条**："规划态·未执行 · [绑定数据入口] [提交策略门演练] [放弃]"，让"AI 组网→人工调→再让 AI 改"的循环路径显式化。
- **数据入口选择器**（`CANVAS_STARTER_SOURCES`）现在是一串 checkbox，100 插件后会很长，改为按阶段分组的可搜索多选，带"已选 N 项"计数。
- 空对话引导语保留范例按钮，但补一条"上次组网"快捷续聊。

## 六、P2 · 导航与信息架构

### 6.1 左侧导航
- **图标去重**：为每个工作台配独立图标（任务编排=节点连线、图谱=共享网络、Run 画布=播放/工作流、知识库=书本、插件=积木、审计=放大镜勾选、量化=折线、AIOps=雷达、审批=签章、风险模拟=盾牌告警），避免同图标多次复用。
- **分组语义微调**：建议改为「总览」「组网与运行（任务编排/图谱/Run 画布）」「资产（知识库/插件）」「业务工作台（审计/量化/AIOps）」「治理（审批/风险）」，并在组标题右侧留快捷计数（如审批中心待办数）。
- 当前选中项已有 accent 底色，补一个左侧 3px accent 指示条，层级更清楚。
- 支持侧栏整体折叠为 56px 图标栏（给画布让宽）。

### 6.2 运行总览页重排（消除空白、接上真实数据）
- 第一行指标卡接真实数据：**已验证插件 100**、**今日 run / 成功率**、**待审批**、**策略裁决次数**、**控制平面版本/连接**；"已启用插件贡献=0"这类占位数字要么接 `verified=100`，要么先隐藏。
- 第二行改为两栏：左「最近运行」迷你列表（复用 RunsPanel 数据，Top5 + 跳转 Run 画布）；右「安全执行边界」说明卡（现有内容）。
- 第三行：策略网关最近裁决流（最近 N 条 allow/deny 时间线）。让首屏成为真正的"驾驶舱"，而不是 4 张卡 + 大片空。
- 指标卡在 <1400px 时 4 列变 2 列（`grid-template-columns: repeat(auto-fit,minmax(...))` 已有，调小 minmax 并让卡片等高）。

### 6.3 顶部状态条瘦身
- 租户/策略/连接三状态合并为一个**环境徽标组**：`● local-dev · 网关托管 · 已连接`，hover 弹出详情；腾出的宽度还给租户切换，彻底解决截断。
- 窗口缩放控件（+/-/%）移入"视图"菜单或只保留快捷键（已有 Ctrl±/Ctrl0），toolbar 只留一个百分比可点复位。

## 七、P2 · 视觉系统细化

- **字号阶梯**：现在 10/12/13px 混用偏多偏小，125% 缩放下 10px 边标签吃力。统一为 12（辅助）/13（正文）/15（卡片标题）/20（页面 H）四档，画布边标签提到 11。
- **等宽字体统一变量**：plugin_id、hash、trace、数字统一走 `--font-mono: "Cascadia Mono", Consolas, monospace` + `font-variant-numeric: tabular-nums`（表格已用，推广到画布与检查器）。
- **层级靠背景而非更多描边**：面板 `--bg-panel`、悬浮 `--bg-panel-2`、hover `--bg-hover` 已有，节点卡建议同体系，减少现在满屏 1px 边框的噪点。
- **焦点可见性**：自定义按钮/画布节点补 `:focus-visible` 描边（窗口控制按钮已有，推广到 run 卡片、节点、AI 面板按钮），键盘可达。
- **状态色一致性**：`RunCanvas.nodeColor` 用了一套硬编码色（#52e08a/#ea6668/#faad14/#9eacea），与全局 `--down/--up` 不完全一致，统一引用 CSS 变量，避免两种绿。
- 滚动条 8px 已不错；AI 面板/画布检查器滚动到边界时加 `overscroll-behavior:contain`，防穿透。

## 十、建议实施顺序

1. **第一批（半天，立即见效）**：3.1 顶部截断、3.2 三栏折叠+空状态引导、6.2 总览接真实数据、默认选中最近成功 run。
2. **第二批（1–2 天，主战场）**：第四节 Run 画布全部（中文节点/泳道/minimap/筛选/检查器）。
3. **第三批（1 天，AI 闭环）**：第五节 AI 助手阶段流与草稿 diff、数据入口分组。
4. **第四批（半天，打磨）**：导航图标、视觉变量、P3 快捷键按需。
