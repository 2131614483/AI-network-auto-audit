# Phase 2：知识输入与文档生命周期

状态：**已完成（2026-09-04 验收；Phase 2.1 加固完成）**。用户于 2026-09-04 明确启动。本阶段把已有的本地文本导入 MVP 提升为可管理、可恢复、可持续扩展的知识工厂；不自动进入图谱自动抽取或第三方工具执行。

## 验收结论

六项交付全部通过：文件夹导入（保留相对路径 + 越界/预算拒绝）、文档软删除回收站/恢复与检索隔离、上传/回收/恢复三写操作经 Policy Gateway 且绑定幂等键、富媒体本地适配器目录只读可见、桌面知识工作台中文文案/确认/空态、全量回归。

## Phase 2.1：上传与测试隔离加固

此前策略网关能够拒绝“同键不同载荷”，但它只缓存策略决定；同键同文件的上传重试仍可能创建新的暂存目录。该缺口已关闭：

1. `knowledge.upload` 现强制要求 `Idempotency-Key`；请求指纹包含文件名、相对路径、SHA256 和大小。
2. 新表 `knowledge.upload_idempotency` 在本机 PostgreSQL 中以 RLS/强制 RLS 保存完成后的**业务响应**。同键同内容只回放原批次和文件结果（每次请求保留自己的 Trace）；同键不同内容或正在处理的重复请求以 409 fail-closed。
3. `audit_network_test` 成为 pytest 的默认原生测试库；通过 `scripts/init-test-postgres.ps1` 显式创建、迁移和验证。它只允许固定测试库名且不执行删除数据库操作，`audit_network` 工作库不再被默认测试写入。
4. 验收新增：缺失幂等键拒绝、同键同文件不重复导入、同键不同文件拒绝、上传幂等记录强制 RLS。隔离库全量回归为 Python `108 passed, 1 skipped`；跳过项是未被本阶段触发的真实 MinerU opt-in 测试。

## 已有基础与真实缺口

已有能力：Markdown/TXT/CSV/DOCX/XLSX 解析、工件 SHA256、版本化文档与块、向量/全文检索、PDF/图片/音视频待处理状态，以及 Electron 的多文件导入。

本阶段补齐：保留文件夹相对路径的选择与上传、文档回收站/恢复、已回收文档从检索结果中隔离、适配器目录的可见状态、文件夹操作 GUI 和审计验证。

## 安全边界

1. 桌面端只能通过受限 IPC 上传用户选定的本地文件；所有写入仍由 API 的 Policy Gateway 裁决。
2. 文件夹导入不得递归执行、解压或运行任意文件；只收集声明后缀，保留相对路径，并设置明确的文件数量/单文件大小预算。
3. PDF/图片仅记录为 `local.mineru` 待处理；音频/视频仅记录为 `local.media` 待处理。适配器声明不能携带任意命令、网络地址或密钥。
4. “删除”是软删除：写入 `knowledge.recycle_bin` 快照，文档和历史块不物理删除；恢复只能还原同一租户的未恢复条目。
5. 文档被回收后不得出现在全文、向量、混合检索或默认文档列表中；保留回收站查询供恢复。
6. 本阶段只提供图谱输入的版本化文档/工件引用；多层知识图谱的自动抽取、跨图桥接策略和大规模 Golden Query 压测属于后续独立 Phase。
