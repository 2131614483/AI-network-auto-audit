# 2026-10-30 分发与功能验收

## 结论

**未通过全功能验收，不应作为正式稳定版发布。** 新合成工作区中，五类页面读取被策略网关要求审批，当前桌面流程不能完成这些读取的通用审批消费；图谱页面还会把读取失败显示成“暂无抽取提案”。这些问题不能通过关闭策略或扩大权限来掩盖。Phase 10 仍在实施中。

后续复测说明：本地源码已修复图谱提案页面的失败提示；最终源码的独立原生构建在策略拒绝时显示错误及重新加载入口，桌面测试 126 项及三源规划、图谱抽取集成测试 14 项通过。GitHub 上 `.4` 安装包尚未包含该修复。其余四类读取阻断、审批消费和异机安装等问题仍未解决，全功能验收结论不变。

验收对象为 Windows 调试版 `0.1.0-debug.20261030.4`，安装包基于提交 `6730c6d` 构建；本次测试源码基于 `23dd81d`，本轮仅新增验收资料和测试修正，产品后台和桌面主进程源码与 `6730c6d` 一致。该包是调试候选，用户机器上先前安装的 `.2` 不会因此自动变成 `.4`。

安装包 `AuditNetwork-0.1.0-debug.20261030.4-win-x64-Setup.exe` 的 SHA-256 为 `07631afd610931ded239fc545a8d7d6b3c79a4f46cf29241ce68980f7af3270e`。

三源组网的集成测试使用独立测试库、合成图谱／历史／知识数据和本机可控模型，覆盖审计主脑、规划、独立评估、补检索与持久化；这不等于在安装版桌面中完成整条操作，也不等于云端模型已验证。

首次完整 Python 回归为 2588 passed、13 skipped、1 failed：本机模拟服务在未读完请求体时返回 401，Windows 偶发连接重置，测试未能收到 HTTP 状态。已修正该测试服务的响应时序，并增加服务直接断开时客户端必须报错的独立检查；相关模型接口测试组 13 项通过，随后完整回归取得上表结果。

首次回归跳过的项目包括本机 Ollama、MinerU、未挂载的真实资料库、已记录的隔离演练，以及两个未找到低距离匹配的图谱召回案例；跳过不能计作通过，尤其不能据此宣称真实资料和图谱语义召回已验收。

## 阻断及未覆盖项

1. 为新工作区设计明确、有限、可审计的只读授权和审批消费路径；保持租户隔离、风险分级和 deny/freeze 优先，不使用通配授权。既有工作区的变更需要明确确认或显式维护流程，不能在应用启动时静默升级。
2. 将读取失败、无权限和确实没有数据区分显示；当前图谱提案首次读取异常没有被页面捕获，初始空列表会显示“暂无抽取提案”。审计页面本轮也出现读取受阻但显示空项目的现象，需分别排查。
3. 使用安装器在干净电脑完成全新安装、首次启动、交互式知识上传／审批、多源组网与评估、退出重启、升级和卸载；核验用户数据、角色与工件的恢复和保留。
4. Docker 引擎当前未运行，容器部署未验收。独立真实外部 AI 服务、真实 API key、公网访问身份体系以及其他操作系统未验收。
5. 重新执行包括图谱、审计、量化、AIOps、规划、审批、设置等页面的成功与失败路径，尤其要验证跨租户隔离、拒绝和过期审批、证据可追溯及错误提示。

## 可重复检查

新工作区读取探针使用实际安装包资源、新目录和本机合成配置；它不会发起云端模型调用，遇到必需页面被阻断时以非零状态结束：

```powershell
node scripts/acceptance-read-paths.cjs build/release-debug-6730c6d/dist/win-unpacked/resources build
```

探针仅记录接口状态和策略裁决，完整合成测试产物留在本机忽略的 `build/` 下；检查完成后会停止其专用数据库。实现契约见 [分发验收契约](../contracts/distribution-acceptance.md)。
