# 内置插件使用说明

> 适用范围：本机 `audit_network` 工程内的 **23 个已验证内置只读插件**。
> 文档更新时间：2026-09-06（R3⑤ `aiops.postmortem-draft`、R3⑥ `quant.research-note-draft` 验收完成后）。
> 详细路线图见 `docs/审计组网插件规划-v1.md`；协议标准见 `docs/插件开发与接入标准-UPP-v1.0.md` 与 `docs/plugin-protocol.md`。

## 1. 当前状态

- 全部 23 个内置插件均为 **read_only**，在**隔离子进程**中执行，经 **Policy Gateway** 持久裁决后放行。
- 插件按《统一插件协议 UPP》组织：`plugin.protocol.json`（身份/能力/治理）+ `plugin.manifest.json` + `plugin.runtime-binding.json`（SHA256 绑定）+ `runtime.py`（隔离子进程实现）。
- R1（6 个只读分析）、R0 提升（3 个）、R2（6 个影子提案）、R3（6 个受审批输出）、Phase 1（1 个文档摄入）全部验收通过。
- 最新全量回归：Python **470 passed, 2 skipped**；Ruff、Mypy（py3.11/py3.12）、桌面 TypeScript typecheck 通过。

## 2. 安全模型（每次调用必经的七道门禁）

`POST /api/v1/plugins/invoke` 的调用链路：

1. **租户校验**：`X-Tenant-Id` 与所有输入工件的 `tenant_id` 必须一致，不一致返回 403。
2. **绑定校验**：`plugin_id` 必须是 runner 固定白名单内的已验证绑定，否则 404。
3. **能力校验**：`capability` 必须与绑定的能力声明完全一致，否则 400。
4. **目录登记**：插件必须在 `plugin_catalog` 中已登记且向当前租户发布，否则 409。
5. **策略裁决**：Policy Gateway 按租户 + 幂等键持久化裁决，`ALLOW` 才继续。
6. **隔离执行**：一次性本机子进程，仅可读取 `AUDIT_PLUGIN_READ_ROOTS` 声明目录内的文件。
7. **审计留痕**：策略决策（ALLOW/DENY/REQUIRE_APPROVAL）与 Trace 全部写入审计链。

插件本身：**无写权限、无网络、无任意命令**；R3 输出草稿永不自动发布/发送/下单，发布、发送、签发、归档、删除均由人在审批后以独立治理身份完成。

## 5. API 调用方法

### 5.1 必需请求头

| 请求头 | 说明 |
| --- | --- |
| `X-Tenant-Id` | 调用方租户 UUID，必须与输入工件 `tenant_id` 一致 |
| `Idempotency-Key` | 幂等键（1–255 字符），同键同载荷重放返回原结果，同键不同载荷返回 409 |
| `X-Trace-Id` | 可选；未提供时由中间件生成，响应头 `X-Trace-Id` 返回同一值 |

### 5.2 请求体（`PluginInvokeRequest`）

```json
{
  "plugin_id": "aiops.postmortem-draft",
  "capability": "aiops.postmortem.draft",
  "postmortem": {
    "incident_proposal": { "<工件引用>" },
    "verification": null
  },
  "max_characters": 20000
}
```

规则：`plugin_id` 必须匹配已验证绑定；`capability` 必须等于绑定声明的能力；**恰好一个**类型化输入字段（`artifact`/`ledger`/`journal`/`document`/`snapshot`/`dataset`/`alerts`/`triage`/`lineage`/`backtest`/`rca`/`proposal`/`investigation`/`finding`/`experiment`/`remediation`/`recovery`/`workpaper`/`report`/`ticket`/`retention`/`postmortem`/`research_note`）；`max_characters` 默认 20000（1–250000）。

### 5.3 工件引用（`PluginArtifactRequest`）

所有插件输入都是**调用方持有的不可变本地工件引用**，字段如下：

```json
{
  "artifact_id": "00000000-0000-0000-0000-000000000001",
  "tenant_id": "00000000-0000-0000-0000-000000000001",
  "uri": "C:\\data\\incident.json",
  "media_type": "application/json",
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "size_bytes": 2048,
  "classification": "internal"
}
```

约束：`sha256` 必须为 64 位十六进制；`size_bytes` 0–50 MB；`classification` ∈ `public|internal|audit_confidential|restricted`。插件子进程只允许读取声明读根内的 `uri`，且校验大小与 SHA256 一致才执行。

### 5.4 响应（`PluginInvokeResponse`）

```json
{
  "plugin_id": "aiops.postmortem-draft",
  "plugin_version": "0.1.0",
  "capability": "aiops.postmortem.draft",
  "policy_decision_id": "<UUID>",
  "input_sha256": "<输入工件 SHA256>",
  "runtime_code_sha256": "<运行时代码 SHA256>",
  "document": { "<输出契约对象>" },
  "trace_id": "<UUID>"
}
```

`input_sha256` 由各插件绑定按输入指纹计算（如 `incident_proposal.sha256`）；`document` 是经 JSON Schema 校验的确定性输出草稿。

### 5.5 PowerShell 调用示例

```powershell
$headers = @{
  "X-Tenant-Id"   = "00000000-0000-0000-0000-000000000001"
  "Idempotency-Key" = "pmd-" + [guid]::NewGuid().ToString("N")
  "Content-Type"  = "application/json"
}
$body = @{
  plugin_id = "aiops.postmortem-draft"
  capability = "aiops.postmortem.draft"
  postmortem = @{
    incident_proposal = @{
      artifact_id = "00000000-0000-0000-0000-000000000001"
      tenant_id   = "00000000-0000-0000-0000-000000000001"
      uri         = "C:\data\incident-proposal.json"
      media_type  = "application/json"
      sha256      = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      size_bytes  = 2048
      classification = "internal"
    }
    verification = $null
  }
} | ConvertTo-Json -Depth 8
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8010/api/v1/plugins/invoke" `
  -Headers $headers -Body $body
```

### 5.6 查看已验证插件（只读，供桌面展示）

```powershell
Invoke-RestMethod -Method Get -Uri "http://127.0.0.1:8010/api/v1/plugins/verified" `
  -Headers @{ "X-Tenant-Id" = "00000000-0000-0000-0000-000000000001" }
```

## 7. R3 受审批输出插件要点

| 插件 | 确定性身份键 | 关键约束 |
| --- | --- | --- |
| `audit.workpaper-export` | `finding_set_sha256 + finding_ids + max_findings` | `status=draft`、no_overwrite、requires_human_approval |
| `audit.report-draft` | `finding_set_sha256 + finding_ids + template_version` | `signature.signed=false`、human_issuance_required |
| `aiops.ticket-draft` | `incident_proposal_sha256 + proposal_id + target_system` | `signature.sent=false`、no_auto_send、requires_target_whitelist |
| `knowledge.retention-recommendation` | `document_sha256 + recommendation + last_access_days + ref_count + classification` | `status=proposed`、no_delete、evidence_immutable |
| `aiops.postmortem-draft` | `incident_sha256 + proposal_id + verification_sha256` | `signature.published=false`、no_auto_publish |
| `quant.research-note-draft` | `evaluation_sha256 + strategy_key + strategy_version` | `signature.published=false`、no_auto_publish、no_order_generation |

所有 R3 输出 `constraints` 均声明 `immutable_source=true`，草稿永不覆盖历史报告/复盘/笔记，落库由治理服务在**人工审批后以独立身份**完成。

## 8. 常见错误

| 状态码 | 场景 | 处理 |
| --- | --- | --- |
| 400 | `capability` 与绑定声明不一致 / 类型化输入不是恰好一个 / 参数越界 | 对照速查表核对 `plugin_id`、`capability` 与输入字段 |
| 403 | 工件 `tenant_id` 与请求租户不一致 / 策略 DENY | 修正租户；向该租户发布对应策略 |
| 404 | `plugin_id` 不在已验证白名单内 | 使用正确的内置插件 ID |
| 409 | 插件未登记发布 / 策略 REQUIRE_APPROVAL / 幂等键复用但载荷不同 | 先执行第 4 节注册与策略发布；更换幂等键 |
| 422 | 工件 `sha256`/`size_bytes`/`classification` 等字段不合法 | 按 5.3 工件引用字段修正 |
