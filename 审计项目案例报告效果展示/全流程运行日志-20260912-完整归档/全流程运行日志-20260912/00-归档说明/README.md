## 三件需要如实说明的事

### 1. 插件在**端口契约层面是孤岛**，不是一张连通的网

100 个节点的 71 条边里，65 条来自脚本固定的主链排序，其余靠 schema 回退补上。
实测：123 个插件中，**每个 contract_id 只被 1 个插件产出**，58 个插件的输入无人提供。

所以这次运行是「**一条主链 + 大量并行独立分析**」的形态，不是「每个插件都吃上一个插件的输出」。
51 个终端节点偏多，正是这个原因——很多节点天然没有下游。

### 2. 策略裁决是**内存里**给出的，未逐节点落库

驱动脚本用 `PolicyEngine(allow=_ALLOW)` 在编排前裁决，所以 `policy.decisions` 表里没有
逐节点记录（时序日志的「策略裁决」段已如实标注）。数据库里 203 条遗留策略集是另一回事，
与本次运行无关。

### 3. 采集时刻 **Ollama 未运行**

`07-环境与版本指纹/ollama-models.json` 记录的是连接失败。
影响：知识库向量检索会 fail-closed（这是设计行为）。本次审计流程**未使用**向量检索，
所以不影响上面的 100/100 结果。

## 怎么复现

```powershell
cd D:\pythonpro\audit_network

# 1) 组网 + 全流程运行（产物写到 12-本次运行产物/，不覆盖任何既有目录）
.venv\Scripts\python.exe docs\全流程运行日志-20260912\10-驱动脚本\运行-全流程捕获.py

# 2) 渲染时序日志 / 逐插件详情 / 中间数据状态 / 数据库快照
.venv\Scripts\python.exe docs\全流程运行日志-20260912\10-驱动脚本\渲染-全流程时序日志.py

# 3) 提取最终结果
.venv\Scripts\python.exe docs\全流程运行日志-20260912\10-驱动脚本\提取-最终结果.py

# 4) 环境指纹
.venv\Scripts\python.exe docs\全流程运行日志-20260912\10-驱动脚本\采集-环境与版本指纹.py
```

> 复现会自动使用本机 `.env` 里配置的 AI 通道。若未配置，组网会 fail-closed 报错——
> 这是设计行为，配置方式见 `docs/cloud-ai-config.md`。

**注意**：渲染与提取脚本里的 `RUN_ID` 是本次运行的 run_id；复现时会生成新的 run_id，
需要相应替换（脚本顶部常量）。
