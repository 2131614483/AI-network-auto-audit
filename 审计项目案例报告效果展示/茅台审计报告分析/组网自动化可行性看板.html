六、两个必须先修的工程阻断（已实测复现）

阻断 A · API 侧的能力召回看不到磁盘上的 123 个插件

API 的 AI 组网入口（/api/v1/topology/planning/ai、/canvas/chat） 走 capability_catalog_from_db()，读的是 DB 蓝图库。本机 local-dev 租户实测 377 行、全部 status='planned'，其中 374 行是契约测试残留（键名形如 it-xxxx-consumer/producer/bridge-dst），真正的语义蓝图只有 3 个。

而磁盘上 domain_catalog('audit') 有 107 capability / 161 端口 / 0 冲突， 却只被桌面画布的改稿路径用上。→ 对 AI 说「生成一份审计报告编制流程」，模型只能看到 1 个真实能力。

阻断 B · 未传目录派生契约，退回 7 条遗留注册表

API 调 AiPlanner.plan() 时没传 port_contracts， 于是闸门落到兜底的 PORT_CONTRACTS —— 只有 7 个端口。 用真实插件 audit.report.report-frame-build 的真端口 project-snapshot 实测：

即：只要模型规划的流程用到任何一个真实审计端口，就一定会被闸门拒绝，连编译器都到不了。
