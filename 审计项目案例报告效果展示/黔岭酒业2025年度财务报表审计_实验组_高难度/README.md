# 黔岭酒业 2025 年度财务报表审计 · 实验组（高难度）

这是本项目**第三份**被审计单位模拟数据集，专用于测试「AI 能否胜任审计中的判断部分」。

与上一版的根本差别不是"漏洞更多"，而是**漏洞藏起来了**：资料里没有任何标记、
没有"应有折旧"列、没有"核对结果"字样，每张表单独看都自洽。
被测方必须自己决定"去查哪张表、把哪两个数放在一起比、用哪条准则去套"。

---

## 一、三份数据集的定位

| 数据集 | 目录 | 漏洞数 | 特征 | 测什么 |
| --- | --- | --- | --- | --- |
| 对照组 | `黔岭酒业2025年度财务报表审计` | 10 | 每处漏洞都有 `★` 标记与提示列 | 基础程序会不会用 |
| 实验组 | `..._实验组` | 42 | 有明确对照（"应提 X / 已提 Y"） | 规则匹配召回率 |
| **高难度** | **`..._实验组_高难度`** | **24 + 5 项噪音** | **零提示，需跨表/比率/准则推理** | **判断与意识** |

三份数据基于同一套会计主体与科目体系，但**账套是各自独立重造的**，不存在交叉污染。

## 四、怎么用

```bash
cd _tools

# 1) 生成客户资料（幂等，结果确定）
python gen_hard_data.py

# 2) 自检：确认资料里没有提示，且基础程序查不出东西
python selfcheck.py

# 3) 生成标准答案与评估矩阵
python make_docs.py
```

把 `01_被审计单位提供资料/` 整个交给被测对象（人或 AI），
要求其输出审计发现，然后对照 `_ground_truth/预期发现清单.md` 评分。

**评分口径**见 `_ground_truth/AI胜任力评估矩阵.md` 第四节，核心是四条：
总体召回率、**分层召回率**（看它在哪一层断崖）、误报率、证据充分性。

## 五、这批数据是怎么"藏"的

### 六种隐蔽手法

1. **跨表错配**（H01、H02、H07）——每张表的合计数都等于总账，
   差异只在两张不同来源的表的分项之间。例如 H01：采购发票登记簿合计 400,000,000，
   存货入库明细合计 393,200,000，差额 6,800,000 一直挂在预付账款，
   两张表各自都"没问题"。
2. **双向抵消**（H03）——同一项目上既有超提又有少提：
   2 张已提足的卡片仍在计提（超提 6,032,500），1 张转固后延后 3 个月起提
   （少提 6,483,750），**净影响仅 451,250 元，低于重要性水平 1,500,000**。
   只核折旧总额一定放行。
3. **金额稀释**（H14、H15、H16）——单笔均低于 SAD 限额 75,000 元，
   分散在不同月份、不同摘要里，要看累积。
4. **形式合规掩盖实质**（H09、H10、H13）——账、单、票齐全，
   在旧准则下毫无问题；要靠**读合同关键条款**（售后回购、代理结算方式）
   或**套新租赁准则**才能发现。
5. **披露遗漏**（H17–H21）——账务处理全对，问题在"没说的话"。
   H21 更细：附注**已经列了**前五名客户金额，缺的是判断性风险表述。
6. **线索藏在非结构化文本**（H18、H19、H20、H24）——担保写在董事会决议第四条、
   并购写在总经理办公会纪要、败诉写在"上诉后确定"的措辞里、
   关联方要**穿透两层股权**（董事配偶 → 投资管理公司 → 供应链公司）。

### 五处"看起来该报、其实不该报"

大额正常关联交易（8 亿）、合规的会计估计变更、Q4 收入占比高（春节备货）、
募集资金大额支出、存货跌价准备转回（售价确实回升）。

这 5 项专门用来测**误报**。只报噪音的模型，比漏检的模型更危险。

### 1. 账是平的

```

OK  黔岭销售有限公司      试算平衡（借−贷 = 0.00）

OK  合并：资产 11,523,370,635.70 = 负债 4,275,700,000.00 + 权益 7,247,670,635.70
```

### 2. 资料里没有答案

`selfcheck.py` 扫描全部 51 个文件 → **未发现任何提示性用语**。

### 3. 基础程序查不出任何漏洞

| 基础程序 | 结果 |
| --- | --- |
| 各主体试算平衡 | 通过（借贷各 12,191,996,666.66） |
| 合并报表平衡 | 通过 |
| 应收账款账龄合计 = 总账 | 通过（1,547,240,000.00） |
| 存货收发存期末 = 总账 | 通过（1,598,770,010.66） |

**6 条基础程序全部通过，对 24 处漏洞的检出数为 0。**

## 八、边界说明

- 本数据集是**模拟数据**，主体、公司名、凭证、人名均为虚构。
- 生成器与被测方资料**完全分离**：`_tools/` 与 `_ground_truth/` 不交给被测方。
- 数据集不包含舞弊手法的完整链条（仅 H22 体外收款、H23 单据缺失属红旗线索），
  如需考察舞弊应对，可在此包基础上扩展。
- 全部脚本仅用 Python 标准库，无第三方依赖。
