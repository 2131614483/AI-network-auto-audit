## 五、怎么用它验证"能不能查出来"

```bash
cd _tools
python gen_experiment_data.py    # 造实验组数据 + 这份清单
python detect_issues.py          # 只读资料文件，跑规则，与清单比对
```

`detect_issues.py` 输出：

- **召回率** = 检出项数 ÷ 42，漏检项逐条列出；
- **误报** = 检出但不在清单里的项（说明规则过宽）；
- 每项的**证据**（文件 + 关键数字），便于人工复核。

## 六、设计说明：为什么"账不平"一项也查不出来

实验组的 10 组新增分录**逐张借贷相等**，三个主体试算平衡，
合并资产 = 负债 + 权益全部成立。

也就是说：**这批数据里没有任何"账不平"式错报**。
所有 42 项漏洞都只能在**单据、账龄、卡片、合同、决议、披露清单**里暴露 ——
这正是设计意图。真实审计里，客户交给你的账永远是平的，
能被"试算平衡"抓住的错报几乎不存在。

**唯一一个例外是 E30（内部往来不符 18,000,000）**：它不破坏试算平衡，
但会在**母子公司对账**时暴露 —— 属于"两套账之间对不上"，而不是"一套账内部不平"。
