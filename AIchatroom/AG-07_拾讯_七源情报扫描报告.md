## 二、脚本与产物

- 脚本：[scan-community-sources.mjs](file:///d:/pythonpro/LocalStock-unified/apps/desktop/scripts/scan-community-sources.mjs)
- 运行目录：`apps/desktop`（Playwright 由该目录 devDependencies 提供）
- 产物目录：`data/runtime/community/`
  - `scan-<YYYYMMDD-HHmmss>.json`：每次运行存档
  - `latest.json`：最近一次结果，供 AI 直接读取

常用命令：

```bash
cd apps/desktop
node scripts/scan-community-sources.mjs                       # 七源全量
node scripts/scan-community-sources.mjs --only cls,jin10 --limit 20
node scripts/scan-community-sources.mjs --proxy http://127.0.0.1:7897 --headed
node scripts/scan-community-sources.mjs --no-browser          # 只跑 HTTP 源
```

参数说明：

| 参数 | 默认 | 含义 |
|---|---|---|
| `--only` | 全部 | 逗号分隔的源 id，如 `cls,jin10,tgb` |
| `--limit` | 10 | 每个源最多输出条数 |
| `--body-limit` | 6 | 需要抓正文的源（tgb/jygs）抓前 N 条正文 |
| `--max-age-days` | 7 | 丢弃超过 N 天的条目（无时间字段的保留） |
| `--timeout` | 20000 | 单请求超时（ms） |
| `--proxy` | `LOCALSTOCK_PROXY` | 浏览器代理，如 `http://127.0.0.1:7897` |
| `--headed` | 否 | 显示浏览器窗口，便于排查登录墙/验证码 |
| `--no-browser` | 否 | 跳过所有浏览器源，只跑 HTTP 源 |

## 三、统一数据结构（AI 消费契约）

每个条目固定字段：

```json
{
  "id": "cls:1234567",
  "source": "cls",
  "kind": "flash",
  "title": "标题（≤120 字）",
  "summary": "摘要（≤300 字）",
  "content": "正文（≤4000 字；无正文时等于标题）",
  "url": "原文链接",
  "author": "作者/机构",
  "publishedAt": "2026-10-28 22:21:27",
  "ts": 1761661287000,
  "tags": ["重要", "代码:600519"],
  "metrics": { "reading": 1234, "comments": 12 }
}
```

`kind` 取值：`flash`（快讯）、`announcement`（公告）、`post`（社区帖）、`hot`（热帖）。

外层结构：

```json
{
  "meta": { "generatedAt": "...", "elapsedMs": 29465, "limit": 10, "only": [], "proxy": null, "browser": "路径", "total": 60 },
  "sources": [{ "id": "cls", "name": "财联社", "type": "http", "status": "ok", "items": 10, "error": "", "note": "", "elapsedMs": 140 }],
  "items": []
}
```

AI 读取建议：
1. 先看 `sources[].status`，`error`/`login_required` 的源不要当成“无消息”。
2. `items` 已按 `ts` 倒序去重，直接顺序消费即可。
3. 判断“是否有正文”用 `content.length` 与 `title.length` 比较；相等即仅标题，不要把它们当全文引用。
4. 引用时必须带 `source` 与 `publishedAt`，不要跨源合并同一事件时丢掉来源。

## 四、各源实测入口与坑（复现用）

### 1. 财联社 cls
- 入口：`https://www.cls.cn/api/cache?app=CailianpressWeb&name=telegraph&os=web&sv=7.7.5`
- 必须带 `Referer: https://www.cls.cn/telegraph`，否则被拒。
- 数据在 `data.roll_data[]`，字段 `id/title/brief/ctime/level`。
- `ctime` 是秒级时间戳。
- 部分“风口研报”只有 title，脚本已回退 `summary/content = title`。

### 2. 金十数据 jin10
- 入口：`https://flash-api.jin10.com/get_flash_list?channel=-8200&vip=1`
- 必须带 `x-app-id`（脚本内置公开值）与 `x-version`。
- 数据在 `data[]`，正文在 `data.content`，时间在 `time`。

### 3. 巨潮资讯 cninfo
- 入口：`POST http://www.cninfo.com.cn/new/hisAnnouncement/query`
- 表单：`pageNum/pageSize/column=szse/seDate=今天~今天/tabName=fulltext`
- **坑**：`column=szse,sse` 会 500；`pageSize=100` 实际只返回 30 条。
- **坑**：同一家公司常一次披露十几份文件，不分页去重会“10 条公告全是同一只股票”。脚本已做最多 6 页累加 + 每代码最多 2 条。
- 公告 PDF：`http://static.cninfo.com.cn/<adjunctUrl>`。

### 4. 淘股吧 tgb
- 列表：`https://www.tgb.cn/bbs/`，块标记 `<div class="Nbbs-tiezi-lists">`。
- 正文：`https://www.tgb.cn/a/{id}`，容器 `div.article-text.p_coten`。
- **坑**：正文 div 内嵌多层 div，按字符串找结束标记会提前截断；脚本用 `sliceDiv()` 按 `<div>` 嵌套深度配平。
- **坑**：列表顺序不固定且混有置顶老帖（可见 09-22、10-23 的帖），脚本先按时间过滤再排序取最新 N 条。
- **坑**：未抓正文的条目 `content` 等于标题，不是空值，AI 不要误判为全文。

### 5. 韭研公社 jygs
- 列表可 HTTP 拿到 Nuxt SSR 的 `/a/{id}` 卡片，但正文需浏览器渲染。
- 正文容器 `.detail-container`；脚本在 DOM 中移除 `.fs28-bold`（标题）、`.username-box`、`.reward_integral`、`.comment-content`、`.operate-box`、`.relay-tea`、`.jc-comment` 后再取 `innerText`。
- 单源耗时约 11 秒（每篇都要 `goto` + 等待 1.2s）。

### 6. 雪球 xueqiu
- 裸 HTTP 直接返回 WAF 挑战页；`stock.xueqiu.com` 返回 `error_code 400016`。
- 可行路径：Playwright 打开首页 → 等待 3 秒拿到 `xq_a_token` 等 Cookie → 在页面内同源 `fetch('/statuses/hot/listV2.json?since_id=-1&max_id=-1&size=N')`。
- 解析 `items[].original_status`，字段 `id/text/title/created_at/user.screen_name/reply_count/retweet_count/fav_count`。

### 7. 开盘啦 kaipanla
- 官网路由仅 `/about`、`/contact`、`/download-app`、`/feedback`、`/timeline`，`/timeline` 为扫码登录页。
- App 接口 `apphq.longhuvip.com`、`apphis.longhuvip.com`、`pchq.kaipanla.com` 均返回空列表或空行。
- 结论：按“只采公开内容”策略，标记 `login_required`，不伪造数据。

## 五、运行环境约束

## 六、已知边界

1. 只采公开内容：雪球、淘股吧、韭研的登录后内容不在范围内；开盘啦无法采集。
2. 正文抓取有配额：`tgb`/`jygs` 只抓前 `--body-limit` 条，其余仅有标题。
3. 快讯类（cls/jin10）本身即短文本，`content` 不会很长，这是数据特性而不是抓取失败。
4. 雪球热帖 API 的可用性依赖首页能否拿到 Cookie，遇 WAF 变更需要重新适配。
5. 本脚本为验证版，尚未接入桌面端 AI 工具网关，AI 目前需直接读取 `latest.json`。
