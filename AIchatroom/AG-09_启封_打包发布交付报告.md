## 三、便携运行时架构（接手必读）

**没有用 PyInstaller**，原因是插件以 `sys.executable -I -c` 子进程方式执行，PyInstaller 打包后 `sys.executable` 不再是 Python 解释器，隔离执行的语义会被破坏。改为"官方独立发行版 + 原样落盘"：

| 组成 | 来源 | 体积 |
|---|---|---|
| CPython 3.12.12 | uv 的 python-build-standalone（`install_only`） | 140 MiB |
| PostgreSQL 16.13 + pgvector 0.8.0 | 本机 PG 安装目录裁剪后复制 | 148 MiB |
| 业务代码 | 仓库工作区拷贝（`apps/ packages/ migrations/ contracts/ plugins/ scripts/ web/ alembic.ini pyproject.toml README.md`） | 6.4 MiB |

产物布局（安装后）：

```text
<安装目录>/
  AuditNetwork.exe
  resources/
    app.asar                 154.1 MiB（out/ 6.1 + node_modules 145.0 + package.json）
    app/                     6.4 MiB   业务代码，可读可查
    runtime/python/python.exe          便携解释器
    runtime/pgsql/bin/pg_ctl.exe       便携数据库
```

数据布局（用户目录，卸载不删）：

```text
%APPDATA%\audit-network-desktop\data\
  pgdata\            数据库簇（initdb 生成）
  logs\postgres.log, api.log, worker.log
  runtime.json       三个随机密码 + 上次成功端口（mode 0600）
  initialized.json   种子/插件/图谱已完成的标记
  ...                其余 .data 内容（drafts、drop、isolated、evidence 等）
```

**校验顺序不可换**：超级用户 `audit_bootstrap` 建库与 `vector` 扩展 → `audit_migrator` 跑迁移 → `audit_app` 起 API。`vector.control` 在 PG16 里不是 `trusted` 扩展，普通角色装不了；反过来先建库再改属主也会踩权限。

**已知体积问题（未修）**：`desktop/package.json` 把 `antd / echarts / three / @types/three` 放在 `dependencies`，electron-builder 因此把 145 MiB 的 `node_modules` 打进 asar。这些库只被 vite 打进渲染层产物，运行期不需要。全部移到 `devDependencies` 可让 asar 从 154.1 MiB 降到约 9 MiB，安装包预计从 189.7 MiB 降到 150 MiB 上下。**未改动，因为要先跑一遍 `package:dir` 验证渲染层不依赖运行期 node_modules。**

## 四、首次启动时序（排查"卡住"时按此对表）

`backend.ts::startPackagedBackend()` 固定顺序：

1. `resolvePaths()`：校验 `runtime/python/python.exe` 与 `runtime/pgsql/bin/pg_ctl.exe` 存在，缺一个立刻抛错（不会静默降级到系统 Python）。
2. `resolvePgPort()`：读 `runtime.json` 的上次端口；若簇存在且 `postmaster.pid` 在，视为残留实例，沿用旧端口；否则探活挑端口。
3. `pickPort()`：默认 8010，被占则顺序试下一个。
4. `savePorts()`：**先落盘再启动**，所以端口在失败后也可查。
5. `startDatabase()`：`initdb`（约 10 秒，`--locale=C`、`scram-sha-256`）→ `pg_ctl start -w -t 90`。
6. `ensureRolesAndDatabase()`：三个角色 + 4 个扩展 + `GRANT USAGE ON SCHEMA public`。
7. `migrate()`：`alembic upgrade head`（migrator 身份）。
8. `provisionDemoData()`：种子 → 插件注册 → 图谱索引 → 写 `initialized.json`。
9. 起 API → `waitForHealth()` 轮询 `/health`（500ms 间隔，上限 90 秒）。
10. 起 worker → 返回 `apiBaseUrl`，主进程回填 `controlPlaneUrl`，关闭启动窗。

**两个必须知道的语义**：

- `initialized.json` 只表示"数据 provision 完成"，**不表示 API 就绪**。判断可用性只能轮询 `/health`，不能看这个文件。写文件发生在第 8 步末尾，API 在第 9 步才起。
- 首次 40–50 秒里窗口必须存在，否则用户以为没启动。启动窗由 `createSplashWindow()` 在 `whenReady` 最早阶段创建，后端日志通过 `splash.update()` 逐条显示。

端口优先级：`runtime.json` 记录 > 环境变量 `AUDIT_NETWORK_API_URL`（仅开发）/ 默认 8010 / 随机空闲端口。数据库默认 54329，避开本机可能已有的 5432。

## 八、踩坑清单（按"会浪费你几小时"排序）

1. **`spawnSync(pg_ctl start)` 永久阻塞**。postmaster 继承 stdout/stderr 管道，父进程等 EOF 等不到。修法：该调用必须 `stdio: "ignore"`。这个坑表现为"首启卡死无日志"，极易误判为数据库损坏。
2. **安装版日志目录要自己 `mkdir`**。改到 `userData/data/logs` 后，`appendFileSync` 在目录不存在时抛 ENOENT，而这段代码在 `whenReady` 里，异常被吞 → 表现是"双击无窗口无报错"。现在 `resolvePaths()` 第一件事就是 `mkdirSync(..., {recursive:true})`。
3. **`ELECTRON_RUN_AS_NODE=1` 会让 exe 变成 Node**。本机宿主环境带这个变量，直接跑安装版会报 `bad option` 且无窗口。测试脚本必须 `env -u ELECTRON_RUN_AS_NODE`。
4. **代理变量大小写重复**。同时存在 `HTTP_PROXY` 与 `http_proxy` 时，PowerShell 的 Env 提供器与 `Start-Process` 会报错。脚本里统一清空四种（含 `ALL_PROXY`）。
5. **psql 传中文按 GBK 编码**。安装脚本里的 SQL 只要含中文就 `invalid byte sequence for encoding "UTF8"`。所有 DDL 只用 ASCII；中文提示放在 Node 侧日志。
6. **electron-builder 清 `dist\win-unpacked` 触发 safe-delete 批量删除拦截**。构建前手工删目录，或改用 `--dir` 单独跑。
7. **npm 默认源不可达**。用 `npmmirror`；`electron-builder` 会缺 `balanced-match@4`，需 `npm i --no-save balanced-match@4` 补。
8. **NSIS `/S` 静默安装在本机不生效**（弹交互窗口，无桌面可点）。自动化验证因此改为直接跑 `win-unpacked\AuditNetwork.exe`，安装器本身只验证了能生成。
9. **pip 阿里云镜像缺 `markupsafe` 的 cp312 wheel**。换清华源解决。
10. **迁移 head 常量有两处**：`apps/api/main.py` 与 `packages/ops/supervisor.py`。只改一处，`/health/ready` 会一直 `migration_head != migration_expected`。

## 十二、给后续 AI 的红线

1. **不要把"安装包能跑"当成"仓库可用"**。二者当前不等价：55 个未跟踪条目里，53 个是产品代码/配置/文档。
2. **不要在没有 Windows 桌面会话的情况下声称 Docker 或安装器验证通过**。没跑就是没跑。
3. **不要为了跑通而降低安全边界**：`REQUIRE_APPROVAL`、RLS、`audit_app` 无 `BYPASSRLS`、迁移显式执行，这四条都不许为"方便演示"而放宽。
4. **不要用系统 Python 或全局 pip 验证**。干净副本 + 全新 venv 是唯一可信口径。
5. **不要删 `%APPDATA%\audit-network-desktop\data`** 来做"重置测试"——那是用户的审计资料。测试一律用 `AUDIT_NETWORK_DATA_DIR` 指到临时目录。
6. **改迁移 head 记得同步两处常量**，否则健康检查永远不 ok。
7. **新写盘代码先过一遍 `data_root()` 清单**（第五节 16 个调用点），只读目录下写文件会在用户机器上炸，而本机开发永远复现不了。
