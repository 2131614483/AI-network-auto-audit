# 审计报告构建器（Audit Report Builder）

## 适用场景

当用户要求输出以下类型文档时，调用本技能：

- 数据处理/组网/流水线任务的**处理结果合格性评估报告**
- 数据处理流水线的**验收报告**（数据资产构建、复算、测试是否合格）
- 数据集**质量观测与核验报告**
- 任何需要"数据即证据、过程可复算、结论可追溯"的审计化叙述

## 核心写作原则

1. **数据即证据**：每个数字都必须来自机器读取原始文件的实测结果，报告内标注"以下全部为计算机读取原始文件的实测结果，非声明值"；禁止凭记忆/声明值编造。
2. **可复算**：所有关键 KPI 必须能由独立脚本逐行重算，结论注明复算方式与通过情况。
3. **可追溯**：每个"发现/缺陷"必须能回溯到具体行号、字段值或单据，而不是主观判断；发现统一编号（F1、F2…）。
4. **结论诚实**：未能验证的环节（如渲染验证、生产执行）必须在"边界声明"中如实标注为待办，不得提前写"已验证"。
5. **开源声明**：数据源在范围章节中写明来源性质（开源仓库 / UCI 等公开数据集 / 内部数据），并声明只读使用、未改写未再分发。

## 报告骨架（按此顺序）

```
# 审计报告：<对象> <结果>合格性评估
- 报告日期 / 审计对象 / 判定（一句话先行给出结论）

## 前言：组网思路（为什么这样组网，为什么有效）   ← 可选，组网类任务必写
- 一、组网思路：起点（数据域清单）→ 目标（可追溯/可复算/可审计）
  分层流水线简图（L0 接入 → L1 清洗 → … → Ln 结论），逐层收敛
  列出 4–6 条关键设计决策（独立接入+指纹、清洗隔离、多路信号互证、
  独立自洽基准旁路、单点融合出口、只读血缘等）
- 二、为什么这样组网有效：可复算 / 可追溯 / 可信有锚 / 信号全谱 /
  结构可靠（无环 DAG）/ 实测闭环（结果与外部基准互验）

## 0. 审计问题、结论与保证限度（先行声明）
- 0.1 本次审计回答的问题：核心问题 + 2–3 个子问题（构建 / 复算 / 发现可复现）
- 0.2 结论摘要：逐项给出"合格/不合格 + 依据"，并给出整体判定
- 0.3 有限保证（Limited Assurance）：明确为有限保证而非合理保证，
  列出未覆盖范围、用途限制、统计外推限制、口径归一说明
- 0.4 不可抗力与审计风险：论证审计风险三要素（固有×控制×检测）映射
  不可抗力情形（来源失实→固有风险、外部篡改→控制风险、环境/安全故障→检测风险）
  ——结论是"有条件的有限保证，不是绝对的"

## 1. 审计范围与对象
- 表格：# | 数据集 | 源文件 | 规模（行×列） | 用途 | 开源来源
- 来源声明：每个数据源的开源/公开/内部属性、仓库或出处、只读使用声明

## 2. 数据（质量观测）
- 每个数据源一节：规模、分布统计（min/P分位/max）、抽样口径、
  实测发现的缺陷（编号 Fn，给出具体行/值）
- 质量控制：0 缺行 / 0 重复 ID / 缺失格等普查结果

## 3. 处理过程
- 从原始文件到产物的完整步骤链（读取 → 指纹 → 解析 → 清洗 → 建模 → 汇总结论），
  每步说明输入、动作、输出

## 4. 原理
- 核心算法/公式的原理级说明（如审计风险恒等式、Benford、IQR、Pearson、
  加权融合公式及其权重），给出阈值与判级标准

## 5. 可靠性
- 来源可信 / 可复算 / 口径修正记录 / 零副作用（只读、无网络等）/ 边界声明（诚实性）

## 6. 结论
- 逐项判定 + 整体判定 + 后续待办；一句话总结"数据即证据…"

## 7. 插件级规格清单（分层清单：插件 / 原理 / 接口）   ← **含组网/插件的任务必写（全量档），不允许缩略**
- 按分层（L0 接入 / L1 清洗 / L2 关联 / L3 建模 / L4 证据 / L5 结论）**每行一个插件**列全，列为：
  分层 · 插件（程序）· 原理（一句话算法说明）· 接口（输入工件 `源.字段` → 输出工件）
- **与 §8.4 的分工（避免同一事实写两处而漂移）**：§7 是**声明式清单**（有哪些插件、彼此怎么连）；
  `传给`（传入样例）/ `传样`（实测产出）**统一放 §8.4**，不在 §7 重复。
- 编号与顺序必须与 §8 一致（P# 全文唯一、连续）。
- 若项目有插件蓝图契约（如 plugin-blueprint.schema.json），声明字段对齐

## 8. 组网拓扑：数据接口连线与运行血缘   ← **含组网/插件的任务必写（全量档），不允许缩略**
- 8.1 组网全景图：ASCII 文本图画分层节点与连线（边编号 E1…En）
- 8.2 连线明细：表格逐条列出**全部**接口边（上游插件输出工件 → 下游插件输入端口 → 传递内容），不允许"节选 N 条"；边数很多时可改用**层间聚合边**（声明为全量）并注明其下承载的程序级边数
- 8.3 结构特征：分层收敛数、汇聚/分叉节点、双源融合、无环性、最长链路、只读血缘
- 8.4 逐插件注释：**每个插件独立一节**，标注 `接口` / `传给` / `传样`（传样必须带实测数字）；"逐插件注释（缩略）"这类写法不合格，必须逐插件展开

## 9. 数据样貌：各数据源实际行示例（原样展示，未改写）   ← **含组网/插件的任务必写（全量档）**
- 每个源展示真实表头 + **≥2 行**原始数据（行内以 ` | ` 分隔字段；小文件全量、大文件抽样并注明"抽样 N 行"）
- 每个源下方附 4 行说明：
  - 业务说明（这份数据在业务上是什么）
  - 流向插件（S1 → P1 ingest.xxx → …，带边编号）
  - 具体算法（该源上跑的精确算法与参数）
  - 目的（该路径的审计目的与实测产出）
```

## 写作细节规范

- 判定给出统一格式：`**X：合格** + 证据`；整体判定明确"合格（演示层面）"等前缀。
- 编号连续性：发现编号、插件编号（P1…Pn）、边编号（E1…En）全文一致，交叉引用。
- 只读约束类项目：在可靠性/原理中声明"全部边为契约引用、无写入、无外部调用"。
- 报告中所有断言尽量以"本批实测 / 0/N 偏差 / 100.0%"等可量化措辞给出，避免"大约/似乎"。

## 详细度分档与量化标准（§7/§8/§9 的达标底线，v1.1）

任何含"组网 / 插件 / 流水线 / 多源处理"的任务，§7、§8、§9 **必须按全量档**产出，不得以"可选"或"缩略"降档。执行判断标准：

| 章节 | 全量档硬性要求 | 不合格样例（禁止） |
| --- | --- | --- |
| §7 插件规格 | 按分层的逐插件清单（**每行一个插件**：分层 / 原理 / 接口 `源.字段` / 输出工件），覆盖**全部**插件、编号连续；传给·传样归 §8.4 | 只给 2–3 个代表插件；纯名称列表；"见上表"式指代 |
| §8.2 连线明细 | **全部**接口边逐条列全（编号 / 上游.工件 / → / 下游.端口 / 传递内容）；边数多时可用**层间聚合边**声明全量并注明其下承载的程序级边数 | "节选 18 条"、"核心边"（在连边 ≤30 时不允许节选） |
| §8.4 逐插件注释 | 每个插件**独立小节**，逐项标注 接口/传给/传样，传样必须带实测数字；"> 缩略约定"后必须逐插件展开 | "逐插件注释（缩略）"三行带过；"见 §7 表" |
| §9 数据样貌 | 每个数据源：真实表头 + **≥2 行原始行**（小文件全量、大文件抽样注明）+ 附 4 行说明（业务说明/流向插件/具体算法/目的） | 数据源缺样貌、只给表头不给行、只"抽样 1 行"带过主核心源 |
| §2 数据观测 | 按源/按域逐节给出规模（行×列）、缺失普查、分布（min/P分位/max 择要） | 只给域汇总一句话 |

### 达标样例（摘自《多源业务数据组网 Demo 审计报告》，作为篇幅与写法标杆）

**§8.4 逐插件注释（每个插件独立一节）：**

> **P16 `recompute.aar`（恒等式复算·自洽基准）**
> - 原理：逐行验证 Audit_Risk = Inherent_Risk × CONTROL_RISK × Detection_Risk（容差 1e-6）。
> - 接口：`ingest.baseline.records → consistency{mismatch}`。
> - 传样：**0/776 偏差（100.0%）**；示例行 `8.574×0.4×0.5=1.7148` ✓。

**§9 数据样貌（每个源附 4 行说明）：**

> ### S6 内控登记 control_register.csv（5 行 × 8 列，全量）
> `control_id | cycle | description | frequency | type | last_performed | evidence_status | notes`
> `C-01 | Disbursement | Check signing authority | ...`
> - 业务说明：本组网把 ……（这份数据在业务上是什么）
> - 流向插件：S6 → P4 `ingest.controls`（E04）→ P10 `scan.controls`（E17）→ …
> - 具体算法：P4 解析 + P10 三规则扫描（证据状态 / 执行日期 / 职责分离）
> - 目的：输出内控缺陷 3 项（C-02 无证据、C-03 SoD）……

篇幅参考：组网类报告的 §7+§8+§9 合计应占全篇 50% 以上（标杆 650 行中该三章合计 400+ 行）。全文总篇幅凡涉及组网不得低于 500 行、35,000 字级别的信息量。

## 交付检查清单

- [ ] 开头有"日期 / 对象 / 判定"三行元信息

- [ ] 每个发现可回溯到行/值/单据
- [ ] 有限保证与不可抗力（映射审计风险三要素）已声明
- [ ] 数据源开源/公开属性已写明
- [ ] 未验证项如实列入边界声明/待办
- [ ] 全文编号（F/P/E）一致
- [ ] 含组网/插件的任务：§7 逐插件清单齐全（每行一插件）、§8.2 全部边逐条、§8.4 逐插件独立小节、§9 每源表头+≥2 行+4 行说明（对照"详细度分档与量化标准"自检）
