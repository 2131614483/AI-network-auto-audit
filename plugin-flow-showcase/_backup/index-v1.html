数据源落差

VIEW 03 · 理论 vs 落库 vs 展示

同一个「插件数据流」概念在系统里存在四套数据，数量落差巨大——这正是图谱/数据流显得单调稀少的根因。

浅蓝 = 理论层（插件注册、静态演示目录）；橙 = 落库层（拓扑库实际登记）；红 = 图谱管理页实际展示（graph 域，与插件零交集）。

迁移进桌面端的三段路径

VIEW 04 · 数据层 → API 层 → 展示层
01数据层统一

以 catalog.plugins 为插件主档，为 24 个插件补齐契约与蓝图

  • 为每个插件定义输入/输出契约，写入 topology.interface_contracts（当前仅 2 条且未绑定蓝图）
  • 逐个 TopologyService.upsert 生成 topology.plugin_blueprints（当前仅迁移种子 3 个：ledger-quality-slot / finding-draft-slot / research-note-slot）
  • 统一蓝图 key 规范，消除双轨：静态目录 audit-ledger-quality-slot vs 落库 ledger-quality-slot

目标：24 插件 → 24 蓝图，输入/输出契约齐全

02API 层扩展

让后端能吐出完整数据流图

  • packages/plugin_topology/service.py list_blueprints()（710-722 行）返回字段扩展：inputContracts / outputContracts / capabilities / memberships
  • 新增聚合端点 /api/v1/topology/dataflow：蓝图 + 契约配对 + 边，一次返回完整图
  • 图谱管理页跨域取数：新增 /api/v1/graph/plugin-dataflow 或复用在 graph 域投影

目标：前端零硬编码，画布数据全部来自 API

03展示层接入

替换硬编码目录，复用本方案视图

  • desktop/src/components/PluginFlowGraph.tsx 改由 dataflow 端点取数，替换 desktop/src/model/pluginTopology.ts 的 pluginTopologyCatalog（291-369 行硬编码 10 蓝图）
  • desktop/src/App.tsx（1315-1324 行）蓝图数据源从 pluginTopologyCatalog.blueprints 切到 API 响应
  • 图谱管理页新增「插件数据流」标签页，直接复用本方案的视图一/视图二

目标：图谱管理页与插件拓扑工作台数据同源；连线数 = 契约配对数（动态）

数据口径：插件/蓝图/边/契约数量来自 2026-09-09 对主库 audit_network（local-dev 租户）的只读查询；静态蓝图目录与集群来自 desktop/src/model/pluginTopology.ts；插件登记来自 catalog.plugins。

「规划建议链」为按能力语义绘制的示意连线，非契约级配对；真实数据流连线仅 document-content@1 一条。
