# Phase 0.2 核心契约

这些 JSON Schema 是控制平面、领域服务、插件和 GUI 之间的唯一数据契约，使用 JSON Schema Draft 2020-12，和 React/Vue/Python/Node 解耦。它们只描述边界消息与声明，不依赖数据库表，也不授予任何执行权限。

## 文件分组

| 文件 | 用途 |
| --- | --- |
| `artifact-ref.schema.json` | 原始文件、底稿、输出和证据的不可变引用 |
| `audit-task-brief.schema.json` | 审计主脑交接的目标、程序、证据要求与验收标准，不含插件执行权限 |
| `mission-spec.schema.json` | 长期任务、预算、验收条件和 AUTO 模式 |
| `plugin-manifest.schema.json` | 插件版本、能力、资源、权限、副作用和 GUI 注册 |
| `unified-plugin-protocol.schema.json` | 跨业务、跨语言的插件能力/接口/治理协议；不含执行绑定 |
| `plugin-cluster.schema.json` | L0 插件集群、调度域、跨图桥接边界和路由预算 |
| `plugin-blueprint.schema.json` | 不可执行的 L1/L2 插件槽位、能力和契约依赖声明 |
| `plugin-topology-release.schema.json` | 集群/蓝图目录的版本、校验和与可复现发布锁 |
| `plugin-routing-plan.schema.json` | 不可执行的插件候选路由计划（只允许 `plan_only`） |
| `policy-decision.schema.json` | Policy Gateway 的 ALLOW/DENY/REQUIRE_APPROVAL/FREEZE 裁决 |
| `policy-rule.schema.json` | 白名单、黑名单、审批和冻结规则 |
| `graph-query-budget.schema.json` | 图谱检索的节点、边、跳数、图数和延迟上限 |
| `knowledge-changeset.schema.json` | 摄入、冲突解决、人工编辑和 Agent 提案的知识变更集 |
| `workflow.schema.json` | 版本化、可补偿、幂等的类型化 DAG |
| `ui-contribution.schema.json` | 框架无关的导航、视图、查询、动作和设置声明 |
| `ui-action.schema.json` | GUI 动作的 capability 与类型化参数契约 |
| `ui-query.schema.json` | GUI 数据查询和响应契约 |
| `ui-slot.schema.json` | 可扩展的稳定插槽白名单 |
| `renderer-descriptor.schema.json` | 核心或隔离扩展渲染器声明 |

## 兼容性规则

1. `schema_version` 和插件/工作流 `version` 使用 SemVer；主框架至少支持当前大版本和前一个大版本。
2. 消费者必须忽略未知可选字段；生产者不得删除或改变已发布字段语义。
3. 不兼容变更必须升主版本并提供迁移器；已发布插件版本不可原地覆盖。
4. GUI 动作只是请求，不是授权。所有动作仍须携带 capability、规范化参数哈希，并经过 Policy Gateway、审批和审计链。
5. Schema 校验通过不代表允许执行；权限、租户隔离、资源上限、证据保存和黑名单规则仍由运行时强制执行。
6. `$ref` 采用同目录相对路径，构建工具应按 URI 基址解析，不应把 Schema 当作数据库模型自动生成表。
7. `UnifiedPluginProtocol` 只用于控制面兼容与规划；它不含入口点、命令、URL 或密钥。实际实现必须在后续阶段通过独立 Manifest、签名、隔离和 Policy Gateway 绑定。

## 组网执行行为约束

Phase 10 的 `collaborative-planning.schema.json` 约定多源协作规划请求，仅允许 `plan_only`；目标条目必须能按 capability 或输出端口检查，输入仅引用已登记工件 ID，租户和 Trace 来自服务端上下文。图谱、历史和知识查询，以及每次模型调用均逐次经过策略网关；候选通过不能授权执行。

候选连线只描述不同插件节点之间的输出到输入；已授权外部输入由请求绑定，不转换成自环。单节点方案可以没有连线。规划角色须按上一轮硬检查反馈修订，不能把端口的名称或方向自行改写；最终检查仍以目录契约为准。

本机模型接口为 Planner 与 Reviewer 分别传入对应的闭合 JSON Schema，接收后仍须本地验证结构、权限和证据。结构化生成不代替独立评审或硬检查。
本机解码器无法编译较大字符串重复上界时，传输 Schema 省略字符串 `maxLength`，完整文本长度仍在接收端按原契约强制验证，响应字节和上下文预算保持有效。

2026-10-28 会话联调约束：允许使用仅监听回环地址的当前 Codex 会话中继。它只接收既有 Planner/Reviewer 消息，将真实请求保存为不可覆盖的交换文件，等待当前会话提供结构化响应；不自行生成答案。每条请求绑定租户、Trace、会话、角色、轮次及消息摘要，响应必须匹配全部绑定并通过原角色结构校验。未提供响应、绑定不符或鉴权失败时不得返回伪造成功。该中继只用于用户授权的合成资料联调，不是当前聊天变成了可独立运行的模型 API。

## 审计主脑任务交接约束（Phase 10）

审计域先检索审计知识，再由独立 `audit_brain` 角色产出 `audit-task-brief.schema.json` 所定义的审计任务说明：目标、范围、风险假设、审计程序、每项程序所需证据和验收标准。说明绑定原始目标与知识快照摘要。主脑不能修改用户目标、预算、工件绑定、权限，也不选择插件连线。未解决的业务依据缺口只能发起知识补查；此时不得进入插件编排。

任务说明通过引用及目标覆盖检查后，才读取插件关系、目录和历史组网经验。候选须显式将每项审计程序映射到节点；评审须绑定任务说明摘要，并逐程序判断方案是否满足所需证据和验收要求。业务依据缺口可退回主脑修订；知识变化使旧任务说明失效。接受前重新核验知识与输入；恢复旧会话时不能沿用没有有效任务说明的审计通过资格。所有角色调用与读取仍使用原策略网关和预算，历史成功不会覆盖审计依据或真实插件契约。

以下约束不新增消息字段或执行权限，适用于现有 DAG 搜索、编译与端口绑定执行：

1. `PortBoundExecutor` 必须将调用方的策略传给隔离运行时，逐节点按实际调用参数重新裁决；不得根据节点声明临时创建允许规则。上层链路获准不代表其中每项能力已获准。
2. 节点只有获得 `ALLOW` 才能启动插件子进程；`DENY`、`FREEZE`、`REQUIRE_APPROVAL` 或无匹配授权时，现有同步执行入口返回失败节点且不发布输出，不自动批准或继续执行该能力。
3. `build_dag(max_nodes=...)` 的节点预算必须是正整数（不接受布尔值），每轮扩展均不得超过上限；未选节点的输出不能进入已覆盖端口集合。
4. `plan_from_dag(max_nodes=...)` 显式给出的节点预算同样是正整数，必须原样传给编译预算；已有 DAG 超出该上限时拒绝编译，不能按实际节点数或默认下限扩大它。省略该参数时保留既有默认预算行为。

## 本地快速校验

在项目根目录执行：

```powershell
Get-ChildItem contracts/jsonschema -Filter *.json | ForEach-Object {
  Get-Content -Raw $_.FullName | ConvertFrom-Json | Out-Null
  Write-Output "OK $($_.Name)"
}
```

这一步只验证 JSON 语法。Phase 0.2 的契约测试还需要使用支持 Draft 2020-12 的校验器，覆盖每个 Schema 的有效样例、缺失必填字段、越界预算、非法能力名、未知 GUI 插槽和禁止副作用组合。

## Phase 10 模型接入模式

桌面 AI 设置增加 `planning_mode`，只接受 `debug` / `external`；缺省为 `debug`。
`debug` 使用绑定租户、Trace 和会话的本机 OpenAI 兼容中继，等待当前 Codex
会话逐次提供真实响应，只供本机独立测试库及显式声明的合成资料联调。
`external` 使用已保存的统一 AI API 配置（OpenAI 兼容或 Ollama）。两种模式共用
审计主脑、规划、独立评估、预算和 Policy Gateway，不提供任何失败后的自动换模。

创建会话时把不含密钥的接入快照存入 `checkpoint_json.model_access` 及创建事件。
恢复时配置与快照不符则失败，须新建会话；终态重放保持原结果。模型调用裁决携带
模式、传输、模型、端点和配置指纹，外部调用按 `external_network` 评估。
历史非终态会话缺接入快照也必须重新提交，避免把旧请求转发到新出口。
设置修改只影响新会话；API Key 只写不读，中继令牌只存在于进程内。

## 桌面工作区数据库维护约束

普通启动不得执行数据库迁移或种子写入。首次初始化必须通过用户明确选择的维护操作
执行；已有工作区需要升级时须先明确选择升级并生成、验证数据库备份。取消、备份
失败、未知版本或无法检查版本时均停止，保留现有数据和备份。数据库维护不授权
任何组网方案执行；模型和业务工具仍须经过 Policy Gateway。

安装版的模型设置持久化到 `AUDIT_NETWORK_DATA_DIR/.env`，与用户工作区一起保留；
配置读取、保存和备份必须指向同一位置。没有设置该数据根时，继续使用项目根的
`.env`，保持开发环境兼容。普通设置保存不得写入只读程序资源目录，不自动搬移或
覆盖已有配置。GUI/API 的设置操作仍须接受原有 Policy Gateway 裁决。
# 本机发行工作区维护契约（2026-10-29）

- 安装器只请求固定的 `initialize` / `upgrade` 操作。明确确认后，先由共用 PolicyEngine 裁决并追加本机维护日志，再执行固定初始化或备份/验证/指定版本迁移；GUI 不能传入命令或 SQL。
- 空库使用受限引导上下文（工作区派生 tenant_id、trace_id、幂等键）；不授予模型、插件执行或外网权限。引导记录在 schema 可用后关联到 local-dev 租户的正式策略审计。
- 已有库升级使用数据库中的实时策略规则，拒绝同样留下裁决；初始化时只为本工作区登记固定维护能力。缺少授权时停止，不通过确认弹窗覆盖拒绝。
- 维护日志追加写入，含前条摘要、裁决、状态和操作引用。重复幂等键只能回读相同操作；冲突、日志损坏或状态未知时停止。失败保留日志和备份。
- 普通启动只检查 schema；不创建维护授权，不运行迁移。应用账号无 BYPASSRLS，迁移只使用独立账号。
- 协作规划端点中未知租户返回 404；只有实际 schema/连接故障返回 503。不能把租户不存在提示成需要迁移。
- 本机工作区可通过 `configure_planning` 明确授权当前配置的外接模型用于 plan_only；先显示模型/端点，确认后核对配置摘要，再由已有实时维护策略授权、记录裁决、写入当前租户的有限能力规则。出站授权绑定模式、模型、端点和配置摘要，不授予插件执行权限。切换配置须重新确认，不自动切模。
- 桌面此入口只操作自己管理的工作区，不能由渲染页提供数据库、租户或 SQL。Debug 在普通工作区保留前置拒绝；合成测试接入沿用独立测试库流程。
- 发行组装使用新的独立 stage 目录，不删除或覆盖旧 stage/安装包；包内排除开发 editable 路径钩子、用户 .env 和缓存，包含项目许可与运行依赖清单。离线构建缺少所需本机工具时停止，不能自动联网下载工具。
